# 小視窗的視窗層級、一起縮小、讀取畫面：手動驗收步驟

對應規格：`doc/specs/companion-window-fixes.md`（R84–R87）。單元測試見 `tests/unit/companion.test.ts`。

| 需求 | 步驟 | 預期結果 |
|---|---|---|
| R84 AC1 | 置頂關閉，主視窗全螢幕時點主視窗 | 小視窗在主視窗後面，影片沒有被擋住 |
| R84 AC2 | AC1 的狀態下按工具列「YouTube 小視窗」 | 小視窗出現在最前面 |
| R84 AC3 | 按小視窗的最小化 | 收到工作列，桌面上沒有小標題列；按工作列還原 |
| R84 AC4 | 開「置頂」後點主視窗（全螢幕）；關掉後再點主視窗 | 置頂時小視窗仍在最上層；關掉後退到後面 |
| R84 AC5 | 開「置頂」→ 關閉 MultiView 再開啟、打開小視窗 | 「置頂」仍是開啟 |
| R84 AC6 | 關閉 MultiView | 小視窗一起關閉 |
| R84 AC7 | 主視窗「置頂」、小視窗沒置頂 → 按工具列「YouTube 小視窗」→ 點主視窗 | 小視窗先出現在前面，點主視窗後退到後面 |
| R85 AC1 | 小視窗開著時主視窗縮到最小，再還原 | 小視窗一起縮小、一起還原 |
| R85 AC2 | 先縮小小視窗，再縮小、還原主視窗 | 只有主視窗還原 |
| R85 AC3 | 小視窗自己縮小、還原 | 主視窗不受影響 |
| R86 AC1 | 從格子開啟「留言」 | 先「讀取中…」，之後直接出現留言區，中間沒有出現整個影片網頁 |
| R86 AC2 | 推薦分頁點一部推薦影片 | 讀取畫面後直接出現新影片的推薦 |
| R86 AC3 | 推薦準備好後切到留言 | 留言已經出現就直接顯示，否則先顯示讀取畫面 |
| R86 AC4 | 讓網頁找不到推薦區 | 15 秒後拿掉讀取畫面，顯示整個網頁 |
| R87 | 安裝後看「⚙ 設定」的版本 | 0.6.1 |

## 2026-11-01 驗收紀錄

以開發版、獨立的測試資料夾執行，透過開發工具（CDP）與 Windows API 操作視窗（不動滑鼠鍵盤），畫面以實際螢幕截圖確認。主視窗全螢幕會蓋住使用者的螢幕，沒有實際切換，以一般大小的主視窗驗證相同的前後關係。

| 需求 | 結果 | 說明 |
|---|---|---|
| R84 AC1 | ✅（一般大小） | 小視窗和主視窗重疊，主視窗取得焦點後蓋住小視窗。全螢幕待使用者確認 |
| R84 AC2 | ✅ | 按工具列按鈕，小視窗出現在主視窗前面 |
| R84 AC3 | ✅ | 縮小時桌面左下角沒有小標題列；工作列的 MultiView 圖示包含小視窗（和主視窗合併在同一個圖示）；還原正常 |
| R84 AC4 | ✅（一般大小） | 置頂開啟時主視窗取得焦點，小視窗仍在上面；主視窗也置頂、切換主視窗置頂後仍在上面（修正：原本主視窗切換置頂後會跑到小視窗前面，改成稍後再把小視窗排回最上面） |
| R84 AC5 | ✅ | 設定檔 `pinned: true`，重開後按鈕仍是開啟 |
| R84 AC6 | ✅ | 關閉 MultiView 後沒有殘留的程式 |
| R84 AC7 | ✅ | 主視窗置頂、小視窗沒置頂：按工具列按鈕小視窗在前，主視窗取得焦點後退到後面 |
| R85 AC1 | ✅ | 主視窗縮小 → 兩個網頁都變成看不見；還原 → 兩個都看得見 |
| R85 AC2 | ✅ | 小視窗先縮小，主視窗縮小再還原後小視窗仍縮小 |
| R85 AC3 | ✅ | 小視窗縮小、還原時主視窗一直看得見；主視窗縮小期間手動還原小視窗、再自己縮小，主視窗還原時小視窗維持縮小 |
| R86 AC1 | ✅ | Rick Astley 留言：約 2 秒「讀取中…」後直接出現留言 |
| R86 AC2 | ✅ | 點推薦影片 → 讀取畫面約 1 秒 → 新影片的推薦 |
| R86 AC3 | ✅ | 推薦顯示期間留言已在背後載入，切過去直接顯示 |
| R86 AC4 | ✅ | 載入不存在的影片（沒有推薦區）→ 約 15 秒後顯示整個網頁（「這部影片已無法播放」） |
| R86 其他 | ✅ | 直播影片的留言區被 YouTube 藏起來 → 約 5 秒後顯示「這部影片目前沒有留言（直播中請看聊天室）」 |
| R87 | 見規格的實作結果 | |

實作時發現：讀取畫面完全不透明時，Chromium 會把被蓋住的網頁當成看不見而暫停繪製，YouTube 不會載入留言（要等 15 秒讀取畫面拿掉才載入），所以讀取畫面設成 98% 不透明。
