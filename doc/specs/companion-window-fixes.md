# YouTube 小視窗的視窗層級、一起縮小、讀取畫面 規格

- 功能代號：`companion-window-fixes`
- Jira：無
- 狀態：已確認、已複查
- 最後更新：2026-11-01
- 前置規格：[youtube-companion-window](youtube-companion-window.md)（R78–R83）。本規格的需求編號從 R84 開始。

## 1. 背景與目標

2026-11-01 使用者測試 0.6.0 回報：

1. 小視窗一直在主視窗上面，主視窗全螢幕時會擋住影片，只能把小視窗縮到最小。
2. 小視窗縮到最小時，在桌面左下角變成一個小的標題列，而且一樣在最上面，全螢幕時會擋住影片。
3. 推薦、留言分頁打開時，會先看到整個 YouTube 影片網頁，之後才變成只有推薦區／留言區。

原因：1、2 是第十八版 R78「附屬主視窗」的做法（Windows 的附屬視窗永遠在主視窗上面，縮小時不進工作列，變成桌面上的小標題列）。3 是網頁要等 YouTube 產生推薦區、留言區後才能只顯示那一區。

使用者選擇（2026-11-01）：小視窗改成一般視窗並提供「置頂」按鈕（預設關閉）；主視窗縮小時一起縮小、一起還原；版本 0.6.1。

## 2. 範圍

**包含：**
- 小視窗改成一般視窗、置頂按鈕（R84）
- 和主視窗一起縮小、一起還原（R85）
- 推薦、留言的讀取畫面（R86）
- 版本號更新並打包（R87）

**不包含：**
- 聊天室、搜尋分頁的讀取畫面（本來就是顯示整個網頁）
- 小視窗的其他功能（R78–R82 不變）

## 3. 共用定義

- **小視窗：** 第十八版 R78 的 YouTube 小視窗。

## 4. 需求清單

### R84：一般視窗與置頂按鈕
- 描述：
  - 小視窗不再附屬主視窗，是一般的視窗：點主視窗時小視窗退到主視窗後面；在工作列有自己的按鈕；縮到最小時收到工作列（不在桌面上留下小標題列）。
  - 小視窗上方（分頁那一行的最右邊）多一個「置頂」按鈕：開啟時小視窗永遠在最上層（包括主視窗全螢幕、主視窗置頂時），再按一次關閉。按鈕開啟時顯示為按下的樣子。
  - 置頂預設關閉；開關的選擇保存在設定檔，下次開啟小視窗時沿用。
  - 主視窗開啟「置頂」（第一版 R8）時，沒有置頂的小視窗也要能叫到主視窗前面：兩個視窗之間的前後和一般視窗相同（點哪個哪個在前），兩個都在其他程式上面。
  - 小視窗「置頂」時，點主視窗（包括主視窗也置頂的情況）後小視窗仍然在主視窗上面。
  - 小視窗被蓋住時，按工具列的「YouTube 小視窗」或格子「YouTube ▾」的「推薦影片」「留言」「聊天室」，小視窗切到最前面（和第十八版 R78 相同）。
  - 關閉 MultiView 時小視窗一起關閉、重開時不自動開啟，維持第十八版 R78。
- 驗收條件：
  - AC1：置頂關閉，主視窗全螢幕時點主視窗 → 小視窗在主視窗後面，影片沒有被擋住。
  - AC2：AC1 的狀態下按工具列的「YouTube 小視窗」→ 小視窗出現在最前面。
  - AC3：按小視窗的最小化 → 收到工作列，桌面上沒有小標題列；按工作列的按鈕還原。
  - AC4：開啟「置頂」後點主視窗（全螢幕）→ 小視窗仍在最上層；關閉「置頂」後點主視窗 → 小視窗退到後面。
  - AC5：開啟「置頂」後關閉 MultiView 再開啟、打開小視窗 → 「置頂」仍是開啟。
  - AC6：關閉 MultiView → 小視窗一起關閉。
  - AC7：主視窗「置頂」、小視窗沒有置頂 → 按工具列的「YouTube 小視窗」，小視窗出現在主視窗前面；再點主視窗，小視窗退到主視窗後面。

### R85：和主視窗一起縮小、一起還原
- 描述：
  - 主視窗縮到最小時（工具列的「─」或工作列），開著的小視窗也縮到最小。
  - 主視窗還原時，因為主視窗縮小而一起縮小的小視窗也一起還原；在主視窗縮小前就已經縮小的小視窗維持縮小。
  - 小視窗自己縮小、還原時不影響主視窗。
  - 主視窗縮小期間，使用者從工作列自己還原了小視窗，之後主視窗還原時不再處理小視窗。
- 驗收條件：
  - AC1：小視窗開著時把主視窗縮到最小 → 小視窗也縮小；還原主視窗 → 小視窗也還原。
  - AC2：先把小視窗縮小，再把主視窗縮小、還原 → 只有主視窗還原，小視窗維持縮小。
  - AC3：把小視窗縮小、還原 → 主視窗不受影響。

### R86：推薦、留言的讀取畫面
- 描述：
  - 「準備好」的判斷：推薦區裡出現影片連結；留言區裡出現留言、或 YouTube 的「留言功能已關閉」等訊息。由網頁裡的偵測程式回報。
  - 讀取畫面蓋在網頁上面，網頁本身仍在背後照常載入（留言要在畫面上才會開始載入）。
  - 推薦、留言分頁的網頁從開始載入，到網頁上出現推薦區／留言區並已經只顯示那一區之前，蓋上一層讀取畫面（深色底，中間顯示「讀取中…」），看不到整個 YouTube 影片網頁。
  - 換影片（連結的格子換影片、點推薦影片）重新載入時一樣顯示讀取畫面。
  - 切換推薦、留言分頁時不重新載入：已經準備好的區域直接顯示；另一個區域還沒出現時（例如留言還在載入）顯示讀取畫面，出現後再顯示。
  - 網頁載入完成後 15 秒仍然找不到推薦區／留言區（例如 YouTube 改版）時，拿掉讀取畫面，顯示整個網頁（和第十八版的技術風險相同，仍可使用）。
  - 影片關閉留言時，YouTube 仍會產生留言區並顯示「留言功能已關閉」（第十八版 R80），視為已經準備好。
- 驗收條件：
  - AC1：從格子開啟「留言」→ 先看到「讀取中…」，之後直接出現留言區，中間沒有出現整個影片網頁。
  - AC2：在推薦分頁點一部推薦影片 → 讀取畫面後直接出現新影片的推薦。
  - AC3：推薦準備好後切到留言 → 若留言區已經出現就直接顯示，否則先顯示讀取畫面。
  - AC4：（以開發工具讓網頁找不到推薦區模擬改版）→ 15 秒後拿掉讀取畫面，顯示整個網頁。

### R87：版本號
- 描述：程式版本號從 0.6.0 更新為 0.6.1，並打包。
- 驗收條件：
  - AC1：`npm run dist` → 產生 `release/MultiView-Setup-0.6.1.exe`；安裝後程式的版本是 0.6.1。

## 10. 複查紀錄（2026-11-01）

| 項目 | 發現 | 處理 |
|---|---|---|
| 主視窗置頂 | 主視窗「置頂」時是最上層視窗，沒有置頂的一般小視窗永遠被蓋住，工具列按鈕也叫不出來 | R84 補充：主視窗置頂時小視窗也在其他程式上面，兩者之間依點擊決定前後；新增 AC7 |
| 兩個都置頂 | 小視窗置頂、主視窗也置頂時，點主視窗會把主視窗排到前面 | R84 補充：小視窗置頂時點主視窗後仍在主視窗上面 |
| 縮小期間手動還原 | 主視窗縮小時，使用者從工作列還原小視窗，主視窗還原時不應再處理 | R85 補充 |
| 準備好的判斷 | 留言區元素一開始就存在但是空的，不能只看元素在不在 | R86 補充以內容判斷；讀取畫面蓋在網頁上，網頁照常載入 |
| 舊設定檔 | 0.6.0 的設定檔沒有「置頂」 | 第 7 節已寫：視為關閉 |
