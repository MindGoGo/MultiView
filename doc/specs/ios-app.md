# iPad／iPhone 版 規格

- 功能代號：`ios-app`
- Jira：無
- 狀態：已確認；步驟 1（R119）、步驟 2（R120–R122 技術驗證）完成，步驟 3、4 實作中
- 最後更新：2026-11-13
- 前置規格：桌面版的所有規格（R1–R118，最後一份是 [page-mode-overlays](page-mode-overlays.md)）。本規格的需求編號從 R119 開始（R119–R144）。
- 使用者的裝置：iPad Pro（M1，128GB）為主要裝置，iPhone 14 Pro（256GB）。
- 參考：使用者 2026-11-13 的選擇：iPad 為主、iPhone 也能用；只給自己用、用 SideStore 安裝（沒有 Mac）；第一版包含核心多格播放、yt-dlp 播放、網頁模式與廣告阻擋、訂閱清單／最愛／歷史；程式放在同一個 repo 的 `ios/` 資料夾。

## 1. 背景與目標

使用者想在 iPad 上使用 MultiView：把畫面切成多格，同時看好幾場直播與影片，集中控制聲音。桌面版是 Electron，iOS 不能跑 Electron，也不能另外執行 yt-dlp 這類程式，所以 iOS 版用 SwiftUI 重新寫一個原生 App，功能和操作盡量跟桌面版一致，把滑鼠、視窗相關的部分改成觸控與 iPad 的多工方式。

使用者沒有 Mac，App 在 GitHub Actions 的 macOS 機器上編譯成沒有簽章的 IPA，再用 SideStore 以使用者自己的 Apple ID 簽章、安裝到 iPad。App 不上架 App Store，因此可以內附 yt-dlp 並讓它自動更新。

開發分成三個階段：

1. **技術驗證（R120–R122）**：先確認風險最大的三件事做得到，結果寫回本規格，必要時調整後面的需求。
2. **核心功能（R123–R134）**：多格播放、聲音、操作、保存。
3. **進階功能（R135–R144）**：yt-dlp、網頁來源、廣告阻擋、YouTube 小視窗、清單與訂閱、設定、匯入桌面版的資料。

## 2. 範圍

**包含：**
- 建置與安裝流程：GitHub Actions 產生 IPA，SideStore 安裝與更新（R119）
- 技術驗證：多格原生播放、多格網頁播放、內嵌 Python 與 yt-dlp（R120–R122）
- 主畫面、版型、分隔線與換位、加入來源（R123–R126）
- 觸控版的工具列與操作列、聲音、播放控制、亮度、畫質與字幕（R127–R131）
- 背景播放、子母畫面、AirPlay（R132）
- 接實體鍵盤時的快捷鍵（R133）
- 保存與還原、記住觀看進度（R134）
- yt-dlp 播放、退回、更新（R135、R136）
- 網頁來源與整頁模式、廣告阻擋、登入狀態（R137–R139）
- YouTube 小視窗（R140）
- 最愛與歷史、訂閱頻道（R141、R142）
- 設定畫面與版本號（R143）
- 匯入桌面版的設定與清單（R144）

**不包含（之後再評估）：**
- 上架 App Store、TestFlight
- 音量超過 100%（桌面版 R98）
- 亮度超過 100%（桌面版 R40、R41 的 105%–150%）：原生播放器的畫面不能直接調亮，只做 20%–100%
- yt-dlp 遇到 Cloudflare 時用模擬瀏覽器重試（桌面版 R114）：需要的 curl_cffi 有原生程式碼，iOS 上不容易編譯
- 分享選單、小工具等「App 延伸功能」：免費 Apple ID 用 SideStore 安裝時，每個延伸功能都會多占一個 App 名額（見第 8 節）；改用網址開啟（R126）
- iCloud 同步、和桌面版之間自動同步（只做手動匯入，R144）
- Mac 版（Mac Catalyst）
- 有 DRM 保護的串流（和桌面版相同）
- 桌面版專屬的功能：無邊框視窗、置頂、最小化（R1、R84、R85）、Windows 安裝檔（R11、R44）

## 3. 共用定義

沿用桌面版的定義：**格位（slot）**、**格子編號**、**顯示中的來源**、**隱藏的來源**（[multiview-player](multiview-player.md) 第 3 節），以及 **YouTube 播放器格子**、**yt-dlp 播放**、**解析**（[ytdlp-playback](ytdlp-playback.md) 第 3 節）。另外：

- **原生播放器：** iOS 內建的 AVPlayer，用來播 mp4、m3u8 和 yt-dlp 解析出來的串流。對應桌面版的「程式自己的播放器」。
- **網頁格子：** 用 WKWebView 顯示的格子，包括 YouTube 內嵌播放器、YouTube 網頁播放、整頁模式和一般網頁來源。
- **操作列：** 每一格下方的按鈕列，對應桌面版 R3 的「每一格的操作按鈕」。
- **工具列：** 畫面上方的全域按鈕列，對應桌面版 R3、R97 的「全域工具列」。
- **點一下：** 手指點一下後放開，沒有移動超過 10pt，按住不到 0.5 秒。
- **長按：** 按住 0.5 秒以上。
- **大螢幕：** App 畫面寬度和高度都至少 600pt，例如 iPad 全螢幕、iPad 分割畫面的一半（橫向）。其他情況是**小螢幕**，例如 iPhone、iPad 分割畫面的 1/3。
- **App 資料夾：** App 的 `Application Support/MultiView/`，對應桌面版的 `%APPDATA%\MultiView\`。

## 4. 需求清單

### 第一階段：建置與技術驗證

### R119：建置與安裝流程
- 描述：
  - iOS 版的程式放在 `ios/`。Xcode 專案由 XcodeGen 依 `ios/project.yml` 產生，repo 裡不放 `.xcodeproj`，避免沒有 Mac 時無法編輯專案檔。
  - 和畫面無關的邏輯（網址判斷、版型、格位、設定與清單的讀寫、yt-dlp 結果的判讀……）放在 Swift Package `ios/MultiViewCore/`，有自己的單元測試。
  - GitHub Actions（`.github/workflows/ios.yml`）在 macOS 機器上執行：
    - 推送到任何分支、而且有改到 `ios/` 時：跑 MultiViewCore 的單元測試，並在 iPad 模擬器上編譯一次。
    - 推送 `ios-v*` 標籤時（例如 `ios-v0.1.0`）：產生沒有簽章的 `MultiView-iOS-<版本號>.ipa`，上傳到 GitHub Releases 的同名版本。
    - 標籤由使用者建立（每次發佈都經過使用者）：在 GitHub 網頁的 Releases 建立新標籤並發佈，這時 Release 已經存在，Actions 只補上標題、說明和 IPA。
  - SideStore 用的「來源」檔 `sidestore-source.json` 列出最新版本的版本號、IPA 下載網址、更新內容。發佈新版時由 Actions 執行 `ios/scripts/make-source.py` 產生，上傳到固定的 GitHub Release `ios-source`（每次覆蓋），所以來源網址永遠是 `https://github.com/MindGoGo/MultiView/releases/download/ios-source/sidestore-source.json`。不放在 repo 的分支裡，避免 Actions 還要回頭推 commit。
  - 更新內容寫在 `ios/release-notes.txt`，用在 GitHub Releases 的說明和 SideStore 顯示的更新內容。
  - 標籤的版本號必須和 `ios/project.yml` 的版本號相同，不同時發佈失敗。
  - iOS 版的 Release 不標成 GitHub 的「最新版本」，README 的桌面版下載不受影響。
  - 來源檔和 IPA 要讓 SideStore 下載得到，repo 必須是公開的。
  - 在 SideStore 加入這個來源後，有新版時 SideStore 會提示更新；更新時保留 App 的資料（設定、清單、登入狀態）。
  - 安裝與更新步驟寫在 `doc/features/ios-app.md`，包括第一次在 Windows 電腦上準備 SideStore 的方式。
- 驗收條件：
  - AC1：推送一個改到 `ios/` 的 commit → Actions 跑完單元測試與模擬器編譯，結果是成功。
  - AC2：推送 `ios-v0.1.0` 標籤 → GitHub Releases 出現 `MultiView-iOS-0.1.0.ipa`，`ios-source` 版本裡的 `sidestore-source.json` 指向這個檔案。
  - AC3：在 iPad 的 SideStore 加入來源網址 → 看得到 MultiView，按安裝後可以開啟。
  - AC4：發佈 `ios-v0.1.1` 後 → SideStore 顯示有更新；更新後原本的格子、清單都還在。
  - AC5：IPA 沒有任何 App 延伸功能（解開 IPA，`PlugIns/` 資料夾不存在或是空的）。

### R120：技術驗證：多格原生播放
- 描述：
  - 做一個驗證用的畫面（只在開發版出現），用原生播放器同時播放 4 格與 9 格，確認：
    1. 4 格可以同時播放，而且可以同時出聲（AVAudioSession 用 `playback` 類別，不和其他 App 混音）。
    2. 每格可以各自靜音、各自調整音量 0%–100%。
    3. 在 iPad 上同時播放幾格 1080p、幾格 720p 不會掉格、不會過熱降速。
  - 結果寫在本規格第 11 節：使用者的 iPad 型號、iPadOS 版本、每種組合的結果。
  - 依結果決定 `3×3` 版型的預設畫質上限（R131）。
- 驗收條件：
  - AC1：4 格 m3u8 直播同時播放 10 分鐘，4 格都有聲音、都不中斷。
  - AC2：其中 1 格音量調到 30%、1 格靜音 → 只有這兩格的聲音改變。
  - AC3：第 11 節記錄了 4 格、9 格的畫質組合與結果。

### R121：技術驗證：多格網頁播放
- 描述：
  - 用 WKWebView 同時放 4 格 YouTube 內嵌播放器（不經過 YouTube 網站，由 App 自己提供載入播放器的頁面），確認：
    1. 可以在格子裡播放，不會自動跳成 iOS 的全螢幕播放器（`allowsInlineMediaPlayback`）。
    2. 不需要使用者先點一下就能開始播放（`mediaTypesRequiringUserActionForPlayback` 設為不需要）。
    3. 多格能不能同時出聲。
    4. 每格能不能各自調整音量。iOS 上網頁不能設定影片的音量，只能靜音或不靜音，所以要試用網頁的 Web Audio 加一道音量控制。
    5. YouTube 內嵌播放器的 API（播放、暫停、跳到某個時間、取得進度、畫質、字幕）都能用。
  - 也用一般影片網站（例如新聞台官網）測一次 3、4 項。
  - 結果寫在第 11 節。依結果調整 R128：
    - 多格不能同時出聲 → 網頁格子同一時間只有一格有聲音（點喇叭時其他網頁格子自動靜音，原生播放器的格子不受影響），並在 R128 寫明。
    - 不能各自調整音量 → 網頁格子的音量滑桿換成只有靜音／不靜音。
- 驗收條件：
  - AC1：4 格 YouTube 內嵌播放器在格子裡同時播放，沒有跳成全螢幕。
  - AC2：第 11 節記錄了同時出聲、各自音量的結果，以及 R128 要怎麼改。

### R122：技術驗證：內嵌 Python 與 yt-dlp
- 描述：
  - App 內附 iOS 版的 Python（Python 3.13 起官方支援 iOS，使用 BeeWare 的 `Python-Apple-support` 打包好的版本），在 App 裡面執行 yt-dlp。iOS 不能另外執行程式，所以 yt-dlp 是在 App 自己的程序裡、用另外的執行緒跑，不是像桌面版那樣執行 `yt-dlp.exe`。
  - yt-dlp 現在解析 YouTube 需要 JS 執行環境（桌面版用 Node 模式的 Electron）。iOS 上沒有 Node，改用 iOS 內建的 JavaScriptCore：寫一個 yt-dlp 的 JS 執行環境外掛，把要執行的 JS 交給 App，由 JavaScriptCore 執行後回傳結果。
  - 確認：
    1. 可以解析 YouTube 直播，得到 m3u8 串流，並用原生播放器播放。
    2. 可以解析 YouTube 一般影片，得到原生播放器能播的格式。原生播放器不能播 DASH，所以要用 HLS 格式或影音合在一起的格式。記錄最高能拿到的畫質。
    3. 可以解析一般影片網站（桌面版 R103），播放時能帶上需要的標頭（桌面版 R110）。
    4. 解析一次要多久；同時解析 4 格時，畫面會不會卡。
    5. 下載新版 yt-dlp（官方的 `yt-dlp` 檔案是 zip 格式的 Python 程式），放到 App 資料夾後可以直接改用新版，不需要重新安裝 App。
    6. App 多大。
  - 結果寫在第 11 節。如果第 2 項只能拿到 360p，在 R135 註明，並把「YouTube 一般影片播放方式」的預設值改成內嵌播放器。
- 驗收條件：
  - AC1：貼上 YouTube 直播網址 → 用 yt-dlp 解析，原生播放器開始播放。
  - AC2：把內附的 yt-dlp 換成下載的新版 → 重開 App 後，設定畫面顯示新版的版本號，可以正常解析。
  - AC3：第 11 節記錄了第 2、4、6 項的結果。

### 第二階段：核心功能

### R123：主畫面與裝置
- 描述：
  - 支援 iPadOS／iOS 17 以上的 iPad 和 iPhone。
  - 畫面只有影片格子，隱藏狀態列，iPad 也隱藏「Home 指示條」（手指往上滑時才出現）。
  - 可以橫向、直向使用。轉向或改變 App 大小時，版型和比例不變，影片不重新載入。
  - iPad 支援分割畫面、Slide Over、幕前調度。App 從大螢幕變成小螢幕時，依 R124 改用小螢幕的版型。
  - 播放中不會自動鎖定螢幕；全部暫停超過 5 分鐘後恢復系統的自動鎖定。
- 驗收條件：
  - AC1：開啟 App → 只看得到格子和分隔線，看不到狀態列。
  - AC2：`2×2` 四格都在播放時把 iPad 轉成直向 → 版型維持 `2×2`，四格都繼續播放。
  - AC3：播放中 10 分鐘不碰螢幕 → 螢幕不會變暗或鎖定。
  - AC4：iPad 切成分割畫面，MultiView 占 1/3 → 改用小螢幕版型（R124 AC3）；拉回全螢幕 → 回到原本的版型。

### R124：版型
- 描述：
  - 大螢幕：和桌面版 R4 相同的 5 種版型 `1`、`2`、`2×2`、`3×3`、`1+3`。
  - 小螢幕：只有 `1`、`2` 兩種。`2` 在畫面比較寬時左右排列，比較高時上下排列。
  - 小螢幕時，設定的版型如果是 `2×2`、`3×3`、`1+3`，暫時用 `2` 顯示（顯示第 1、2 格），其他格暫停，回到大螢幕時恢復原本的版型。這種暫時的切換不保存、不改變設定的版型，也不顯示「有 N 個來源暫時隱藏」的提示。
  - 小螢幕時在工具列選了 `1` 或 `2`，設定的版型就改成選的版型。
  - 其他規則和桌面版 R4 相同（隱藏的來源、預設版型 `2×2`）。
- 驗收條件：
  - AC1：iPad 全螢幕 → 工具列有 5 種版型可以選。
  - AC2：iPhone 直向，版型 `2` → 兩格上下排列；轉成橫向 → 左右排列，不重新載入。
  - AC3：iPad 上設成 `2×2` 四格都在播放，切成分割畫面的 1/3 → 顯示第 1、2 格，第 3、4 格暫停；拉回全螢幕 → 回到 `2×2`，第 3、4 格維持暫停。
  - AC4：AC3 的狀態下關閉 App 再開啟（全螢幕）→ 版型是 `2×2`。

### R125：分隔線與換位
- 描述：
  - 分隔線看起來和桌面版一樣是 2pt，但手指可以按的範圍是 24pt 寬。拖曳分隔線調整比例，規則和桌面版 R5 相同（最小格子大小、每種版型各自的比例），雙擊分隔線回到平均分配。
  - 換位：長按某一格的「移動」按鈕後拖到另一格放開，兩格的內容互換，規則和桌面版 R6 相同（不重新載入、聲音與亮度跟著影片）。拖曳中被拖的格子半透明顯示，經過的格子顯示外框。
  - `1` 版型、小螢幕的暫時版型（R124）、單格全螢幕時不顯示「移動」按鈕。
- 驗收條件：
  - AC1：在 `2` 版型拖曳中間的分隔線 → 兩格大小跟著改變，影片不中斷。
  - AC2：手指按在分隔線旁邊 10pt 的地方拖曳 → 仍然可以拖動分隔線。
  - AC3：在 `1+3` 把第 4 格的「移動」按鈕拖到第 1 格 → 兩格互換，都繼續播放。
  - AC4：拖曳中放開在原本的格子 → 沒有變化。

### R126：加入來源
- 描述：
  - 空白格顯示網址輸入框、提示文字「貼上 YouTube、mp4、m3u8 或影片網頁的網址」，旁邊有 iOS 的「貼上」按鈕（按下時系統不會再跳出允許貼上的詢問），還有「開啟 YouTube」「清單」按鈕（桌面版 R71、R21）。
  - 支援的網址和不支援的網址處理和桌面版 R2、R12 相同（同一套網址判斷邏輯，由 `src/lib/source.ts` 改寫成 Swift，用相同的測試案例對照）。
  - 用網址開啟：App 支援 `multiview://open?url=<網址>`。使用者可以在 iOS「捷徑」App 做一個「分享到 MultiView」的捷徑，從 Safari、YouTube App 的分享選單把網址送過來。收到網址時：
    - 放進第一個顯示中的空格；沒有空格時，依桌面版 R64 讓使用者選擇要取代的格子。
    - App 原本沒開時，先還原上次的狀態再放入。
  - 已經有影片的格子，操作列的「更換網址」打開一個小視窗：輸入框先填入目前的網址，有「貼上」「取消」「確定」；網址不支援時在小視窗裡顯示「不支援的網址」，不關閉。規則和桌面版 R2 AC8 相同。
  - 所有網址輸入框（空白格、更換網址）有內容時，右邊顯示清除按鈕，按下清空並保持輸入狀態。
- 驗收條件：
  - AC1：在 Safari 複製 YouTube 網址 → 在 MultiView 空白格按「貼上」→ 直接開始載入，不需要按 Enter。
  - AC2：貼上 `ftp://example.com` → 顯示「不支援的網址」，格子維持空白。
  - AC3：在 Safari 用分享選單執行「分享到 MultiView」捷徑 → 切到 MultiView，網址放進第一個空格。
  - AC4：四格都有影片時用 AC3 的方式送網址 → 顯示選擇要取代哪一格的畫面。
  - AC5：按「更換網址」→ 輸入框是目前的網址；按清除按鈕 → 輸入框清空，可以直接貼上或輸入新的網址。

### R127：觸控版的工具列與操作列
- 描述：
  - 平常畫面上只有影片（和桌面版 R3 相同）。
  - **影片模式的格子點一下：** 這一格出現操作列，畫面上方出現工具列；手指離開螢幕 3 秒後兩者都隱藏。
  - **每一格的喇叭按鈕：** 工具列顯示時，每一格（有來源的）左上角都有喇叭按鈕，靜音的格子顯示劃掉的喇叭。按下只切換那一格的聲音，不顯示那一格的操作列、不影響其他格子（R128 的多格聲音）。觸控沒有「滑鼠移上去」，點格子又會變成只聽那一格，所以要有不用先點格子就按得到的喇叭。最上面一列的格子，喇叭按鈕往下移，避開工具列。工具列隱藏時，只有有聲音的格子顯示小喇叭圖示（不能按）。操作列或工具列顯示時，點同一格的影片區域只切換聲音（R128），不會隱藏。點操作列、工具列以外的空白處（例如分隔線外的黑邊）立刻隱藏。
  - **整頁模式的格子：** 點網頁就是操作網頁，不顯示操作列和工具列。格子下緣中間顯示小把手（和桌面版 R117 相同），點小把手才展開操作列和工具列。
  - **空白格：** 一直顯示網址輸入框；工具列用畫面上方中間的小把手叫出（所有格子都是空白或整頁模式時才顯示這個小把手）。
  - 操作列的按鈕和桌面版相同（喇叭、音量、亮度、播放／暫停、單格全螢幕、移動、更換網址、選單、移除），按鈕最小 44pt。格子太窄放不下時，「移動」以外的次要按鈕收進「⋯」選單，不可以被截掉。

  - 原本桌面版用右鍵的選單（R27），改成長按影片區域。

- 驗收條件：
  - AC1：點一下 `2×2` 的第 1 格 → 第 1 格出現操作列，上方出現工具列；3 秒後都消失。
  - AC2：整頁模式的格子 → 點網頁上的連結會換頁，不出現操作列；點下緣的小把手 → 出現操作列。

  - AC4：長按 YouTube 格子的影片區域 → 出現桌面版右鍵選單的項目。

### R128：聲音控制
- 描述：
  - 和桌面版 R7 相同：點一下有影片的格子 → 只有這一格有聲音（獨占聲音）；按喇叭按鈕（操作列上的，或工具列顯示時每一格左上角的，R127）→ 只切換這一格（多格聲音）；每格音量 0%–100%；有聲音的格子左上角顯示小喇叭。
  - **網頁播放的格子同一時間只有一格有聲音**（R121 實測，2026-11-13）：iOS 不讓兩個網頁同時出聲，第二個網頁出聲時系統會把第一個暫停。所以 YouTube 內嵌播放器和網頁來源的格子，按喇叭取消靜音時，其他這類格子自動靜音，並提示「YouTube 和網頁的格子同一時間只能有一格有聲音」。原生播放器的格子（mp4、m3u8、之後的 yt-dlp 播放）不受影響，可以和其他格子同時出聲。
  - 切換聲音時被系統暫停的網頁播放格子（已經靜音的），約 1 秒後自動繼續播放。
  - YouTube 內嵌播放器和網頁來源沒有音量滑桿，只有靜音開關（iOS 上網頁不能設定影片的音量）。
  - 音量用按鈕＋彈出滑桿（桌面版 R42），最高 100%，不做 R98 的 200%。
  - 系統音量鍵調整的是整台裝置的音量，不改變每格的音量。
  - 其他 App 開始播放聲音（例如來電、別的影片 App）時，MultiView 全部暫停；中斷結束後，系統表示可以恢復時，恢復中斷前正在播放的格子。
  - 拔掉耳機時全部暫停（iOS 的慣例）。
- 驗收條件：
  - AC1：第 1、2 格都有聲音，點一下第 3 格 → 只有第 3 格有聲音。
  - AC2：兩格都是 m3u8，只有第 1 格有聲音，叫出工具列後按第 2 格左上角的喇叭 → 第 1、2 格都有聲音。
  - AC5：兩格都是 YouTube 內嵌，只有第 1 格有聲音，按第 2 格左上角的喇叭 → 只有第 2 格有聲音，出現提示；第 1 格約 1 秒後繼續播放（沒有聲音）。
  - AC3：播放中有來電，掛斷後 → 原本在播的格子恢復播放。
  - AC4：戴藍牙耳機播放中，把耳機收回盒子 → 全部暫停。

### R135：yt-dlp 播放與退回

### R136：yt-dlp 更新
- 描述：
  - App 內附打包當時的 yt-dlp（放在 App 裡的 `site-packages`，不能修改）。更新時下載的新版放在 App 資料夾的 `bin/yt-dlp.zip`；有這個檔案時 Python 優先載入它，沒有時用內附的（對應桌面版 R91）。
  - App 的版本換了的時候（和 `bin/update.json` 記錄的不同），內附的 yt-dlp 可能比較新，所以刪掉下載的那一份，並把上次檢查的時間歸零，之後照常重新檢查更新。
  - 更新方式：向 GitHub 查詢 yt-dlp 最新穩定版的版本號，比目前使用的新才下載。下載官方的 `yt-dlp` 檔案（zip 格式的 Python 程式）和 `SHA2-256SUMS`，驗證雜湊值後存成 `bin/yt-dlp.zip`。查詢、下載或驗證失敗時保留原本的，播放不受影響。
  - **新版在下次開啟 App 時生效**：已經載入的 yt-dlp 不能在執行中換掉。下載完成後，齒輪選單顯示「重新開啟 App 後使用 <版本>」。
  - 自動更新的時機：
    1. 開啟 App 約 5 秒後，距離上次檢查超過 24 小時 → 在背景檢查，不顯示任何訊息；24 小時內再開啟不重複。
    2. 解析失敗，而且錯誤看起來是 yt-dlp 太舊 → 這一格依 R135 退回內嵌播放器，同時在背景更新；有下載到新版時提示「yt-dlp 已下載 <版本>，重新開啟 App 後生效」。10 分鐘內只因為這個原因更新一次。和桌面版 R92 不同：不能更新完馬上重新解析。
  - 同一時間只進行一個更新；自動和手動同時發生時共用同一次的結果。
  - 自動更新遇到低數據模式時不下載；手動更新不受限制。
  - 新版 yt-dlp 需要的 JS 解題程式和 App 內附的版本不同時，允許 yt-dlp 從它自己的 GitHub 下載對應的版本（yt-dlp 會檢查雜湊值）。
  - 下載的新版載入失敗時（檔案損毀）：自動改用內附的版本，刪掉下載的檔案，之後重新下載。
  - 齒輪選單顯示目前使用的 yt-dlp 版本，以及「檢查 yt-dlp 更新」；手動檢查完成後提示「yt-dlp 已下載 <版本>，重新開啟 App 後生效」「yt-dlp 已經是最新版」或「yt-dlp 更新失敗：<原因>」（對應桌面版 R93）。
  - 上次檢查的時間、上次開啟時的 App 版本記錄在 App 資料夾的 `bin/update.json`。
- 驗收條件：
  - AC1：有比內附更新的 yt-dlp 時，開啟 App 一會兒後打開齒輪選單 → 顯示「重新開啟 App 後使用 <新版>」；從 App 切換器滑掉再開啟 → 選單顯示新版的版本號，YouTube 照常用 yt-dlp 播放。
  - AC2：24 小時內再開啟 App → 不重複檢查。
  - AC3：按「檢查 yt-dlp 更新」→ 顯示三種提示之一。
  - AC4：開啟低數據模式 → 不自動更新；按「檢查 yt-dlp 更新」→ 照樣更新。
  - AC5：把 `bin/yt-dlp.zip` 換成壞掉的檔案（測試用）→ 開啟 App 後 YouTube 照常用內附的 yt-dlp 播放，壞掉的檔案被刪掉。

- 描述：
  - 規則和桌面版 R17、R70、R73 相同：網頁來源預設開啟，每格各自切換，YouTube 內嵌播放器不阻擋。
  - 改用 WebKit 的內容阻擋規則（WKContentRuleList）。EasyList 在打包時（不是在 iPad 上）轉成 WebKit 的規則格式，放進 App。WebKit 一份規則清單最多 15 萬條，超過時分成多份。
  - 第一次開啟 App 時把規則編譯起來（可能要幾秒，在背景進行）；編譯完成前開啟的網頁格子先不擋，編譯完成後不自動重新載入。
  - 只能擋網路請求和隱藏元素，不能像桌面版那樣在網頁裡執行比較複雜的阻擋程式。YouTube 網頁模式（R70）的廣告阻擋做到哪裡，依實際測試在第 11 節記錄。
- 驗收條件：
  - AC1：廣告阻擋開啟 → 測試頁請求 `https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js` 被擋下，一般網址的請求正常。
  - AC2：在其中一格關閉廣告阻擋 → 那一格重新載入，不再阻擋；其他格仍然阻擋。
  - AC3：開啟飛航模式後開啟 App → 廣告阻擋照樣啟用，不顯示錯誤。

### R139：登入狀態
- 描述：和桌面版 R18 相同：網頁格子共用同一份 Cookie 與網站資料，保存在 App 裡，重新開啟 App 後仍然是登入狀態。設定畫面有「清除網站資料」，按下後確認才清除。
- 驗收條件：
  - AC1：在整頁模式登入 YouTube → 關閉 App 再開啟 → 仍然是登入狀態。
  - AC2：按「清除網站資料」並確認 → YouTube 變成未登入。

### R140：YouTube 小視窗
- 描述：
  - 桌面版的 YouTube 小視窗（R78–R83、R86、R106、R107）：推薦影片、留言、聊天室、手機版搜尋，iOS 版改成兩種開法：
    - 大螢幕：從畫面右側滑出的側邊面板（寬 360pt，蓋在影片上方），和清單面板（R141）用同一個位置，一次只開一個。
    - iPad 在幕前調度或分割畫面時，也可以長按工具列的按鈕，選「在新視窗開啟」，開成 MultiView 的第二個視窗（不占 App 名額，只是同一個 App 的另一個畫面）。
  - 小螢幕：開成從下方拉起的面板。
  - 內容跟著最後點過的 YouTube 格子，和桌面版相同。
- 驗收條件：
  - AC1：點一下 YouTube 格子後按工具列的 YouTube 按鈕 → 右側出現面板，顯示這部影片的推薦影片；切到「留言」分頁 → 顯示留言。
  - AC2：在面板中點一部推薦影片 → 放進格子（規則和桌面版 R79 相同）。
  - AC3：iPad 用幕前調度，選「在新視窗開啟」→ 出現第二個 MultiView 視窗，顯示同樣的內容。

### R141：最愛與歷史
- 描述：
  - 清單面板（R21、R58、R105）、最愛（R22）、歷史（R23），規則和桌面版相同，存在 App 資料夾的 `lists.json`，格式和桌面版相同。
  - 放進格子：點一下放進第一個顯示中的空格；沒有空格時跳出選單「沒有空格，要取代哪一格？」，選了就更換那一格的網址（R64）。長按後拖到格子放開（取代桌面版的拖曳）之後再做。
  - 加入最愛：操作列的星號按鈕，名稱用影片的標題；已經在最愛裡時星號是實心的，再按一次移除（R22）。
  - 編輯：往左滑出「編輯」「刪除」（iOS 清單的慣例），取代桌面版的按鈕。
  - 清單面板的位置同 R140。
- 驗收條件：
  - AC1：`2×2` 第 1、2 格有影片，點一下最愛的一筆 → 放進第 3 格。
  - AC2：長按最愛的一筆，拖到第 1 格放開 → 第 1 格改播這一筆，保留聲音設定。
  - AC3：往左滑一筆 → 出現「編輯」「刪除」；按「刪除」→ 這一筆消失。

### R142：訂閱頻道
- 描述：
  - 訂閱頻道與最新影片（R59）、正在直播的標示（R60），規則和桌面版相同。
  - 從 Google Takeout 匯入（R61）：按「匯入」後打開 iOS 的「檔案」選擇器，可以選 Takeout 的 zip 檔或裡面的 `subscriptions.csv`。
  - 訂閱存在 `lists.json`（和桌面版相同）。
- 驗收條件：
  - AC1：把 Takeout 的 zip 存到 iPad 的「檔案」→ 在 MultiView 按「匯入」選這個 zip → 清單出現訂閱的頻道。
  - AC2：有頻道正在直播 → 清單中那個頻道顯示直播標示，點一下放進空格開始播放。

### R143：設定畫面與版本號
- 描述：
  - 工具列的「設定」打開設定畫面（iPad 是中間的小視窗，iPhone 是整頁），內容對應桌面版 R96：播放方式、yt-dlp 版本與更新（R136）、匯入桌面版資料（R144）、清除網站資料（R139）、版本號。自動改用網頁播放（R49）等網頁來源（R137）做好後再加。
  - 工具列的按鈕放不下時（iPhone 直向），工具列可以左右捲動。
  - iOS 版的版本號從 `0.1.0` 開始，和桌面版的版本號分開。設定畫面顯示「MultiView iOS 0.1.0（yt-dlp 2026.xx.xx）」。
  - 每次發佈新版時更新 `ios/project.yml` 的版本號，並推送對應的 `ios-v<版本號>` 標籤（R119）。
- 驗收條件：
  - AC1：打開設定 → 看得到版本號與 yt-dlp 版本。
  - AC2：在設定把 YouTube 直播播放方式改成內嵌播放器 → 已經在播放的 yt-dlp 格子依桌面版 R88 的規則切換。

### R144：匯入桌面版的設定與清單
- 描述：
  - 設定畫面有「匯入桌面版資料」，按下後打開 iOS 的「檔案」選擇器，可以選桌面版的 `settings.json`、`lists.json`（一次選一個或兩個都選）。整個資料夾壓縮成的 zip 檔之後再支援。使用者先把檔案放到 iCloud 雲碟、OneDrive 等 iPad 讀得到的地方。
  - **設定（`settings.json`）：** 取代目前的版型、比例、9 個格位的來源、聲音、亮度、播放方式設定、觀看進度。取代前顯示確認視窗「目前的格子會被取代」。
    - iOS 不用的欄位（視窗位置、置頂、YouTube 小視窗的位置）忽略。
    - 超過 iOS 範圍的值改成 iOS 的上限：音量超過 100%（桌面版 R98）當作 100%，亮度超過 100% 當作 100%（R130）。
    - 匯入後所有格子維持暫停（和開啟 App 時相同）。
  - **清單（`lists.json`）：** 合併進目前的清單，不需要確認。
    - 最愛：網址相同的視為同一筆，保留 iPad 上的名稱；其他的加在最後面。
    - 歷史：網址相同的保留最後播放時間比較新的那一筆，依時間重新排序；超過桌面版的筆數上限（R23）時刪除最舊的。
    - 訂閱頻道：頻道代碼相同的視為同一個，其他的加入。
  - 檔案格式錯誤、不是 MultiView 的檔案時，顯示「無法讀取這個檔案」，目前的設定與清單都不變。兩個檔案一起匯入時，其中一個錯誤不影響另一個，最後顯示各自的結果。
  - 匯入完成後顯示結果，例如「已匯入設定；最愛新增 12 筆、歷史新增 30 筆、訂閱新增 5 個頻道」。
- 驗收條件：
  - AC1：在桌面版設好 `2×2` 四個來源，把 `settings.json` 放到 iCloud 雲碟，在 iPad 匯入並確認 → 版型變成 `2×2`，四個來源相同，全部暫停。
  - AC2：桌面版某一格音量 150%、亮度 130% → 匯入後那一格音量 100%、亮度 100%。
  - AC3：iPad 和桌面版的最愛各有 3 筆，其中 1 筆網址相同 → 匯入 `lists.json` 後最愛有 5 筆，提示「最愛新增 2 筆」。
  - AC4：選一個隨便的文字檔 → 顯示「無法讀取這個檔案」，格子和清單都不變。
  - AC5：在確認視窗按「取消」→ 設定不變。

## 6. API 變更

無。iOS 版和桌面版一樣是獨立的 App，沒有後端 API。

## 7. 資料表變更

無。`settings.json`、`lists.json` 的格式和桌面版相同（R134、R141），iOS 不用的欄位不寫入。yt-dlp 的更新紀錄存在 App 資料夾的 `bin/update.json`（和桌面版相同）。

## 8. 非功能需求

- **免費 Apple ID 的限制：** 用免費 Apple ID 在 SideStore 安裝時，App 每 7 天要重新簽章一次（SideStore 可以在 iPad 上自己完成，但要定期打開 SideStore）；同時最多 3 個自己簽的 App（SideStore 本身占 1 個）；每 7 天最多註冊 10 個 App 識別碼。所以 MultiView 只用 1 個識別碼，不做 App 延伸功能，也不使用免費帳號不能用的 iOS 功能（例如推播通知、iCloud）。
- **效能：** iPad 上 `2×2` 播 4 路 1080p 直播 30 分鐘不當掉、不凍結（和桌面版相同）；`3×3` 依 R120 的結果。開啟 App 到看到格子不超過 2 秒（Python、yt-dlp、廣告阻擋規則都在背景準備）。
- **App 大小：** IPA 預計 60–80MB（Python 約 30–40MB、yt-dlp 約 3MB、廣告阻擋規則約 2MB）。R122 驗證後記錄實際大小。
- **安全：** yt-dlp 的更新檔必須通過官方 `SHA2-256SUMS` 的雜湊值驗證（R136）。用網址開啟（R126）只接受 http(s) 網址，依 R2、R12 的規則判斷。解析得到的串流網址不寫進設定檔（和桌面版相同）。
- **GitHub Actions 的用量：** 公開的 repo 使用 macOS 機器不收費；私人 repo 的 macOS 機器用量是 Linux 的 10 倍，要注意免費額度（未決事項）。
- **測試：** MultiViewCore 的邏輯（網址判斷、版型、格位、設定與清單的讀寫、yt-dlp 結果判讀、更新的協調）寫成單元測試，網址判斷沿用桌面版 `tests/unit/` 的測試案例。畫面、播放、手勢在 iPad 上手動驗收，清單放在 `tests/manual/ios-app.md`。因為沒有 Mac，所有自動測試都在 GitHub Actions 上跑。
