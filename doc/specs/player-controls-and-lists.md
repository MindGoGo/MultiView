# 進度條、單格全螢幕、最愛與歷史清單、畫質 規格

- 功能代號：`player-controls-and-lists`
- Jira：無
- 狀態：已確認、已複查
- 最後更新：2026-10-08
- 前置規格：[multiview-player](multiview-player.md)（R1–R11）、[web-page-source](web-page-source.md)（R12–R18）。本規格的需求編號從 R19 接續，沿用前置規格的「共用定義」。

## 1. 背景與目標

使用者希望在多畫面播放時，能像一般播放器一樣拖曳進度、把某一格放大專心看、把常看的影片存成清單快速放回格子，並改善 YouTube 在小格子裡畫質偏低的問題。

## 2. 範圍

**包含：**
- 每格的進度條，直播可以倒轉時能回放並「回到直播」
- 每格的「全螢幕」按鈕：放大這一格，其他格暫停
- 最愛清單、歷史紀錄（分開），都可以改名稱、改網址、刪除
- 每格的畫質選項（自動／高畫質），適用 YouTube 和 m3u8
- 版本號更新為 0.2.0（R25）

**不包含：**
- 直接拖曳影片畫面換位置（使用者選擇維持現狀，繼續用「移動」按鈕）
- 用鍵盤快轉、倒轉（例如方向鍵）
- 最愛清單手動排序、分資料夾
- 匯出／匯入清單、雲端同步
- mp4 和一般網頁來源的畫質選擇（mp4 只有一種畫質；網頁的畫質由網站決定）
- 指定確切的畫質數值（例如 720p、1440p），只有「自動／高畫質」兩種

## 3. 共用定義

- **可回放的直播：** 播放器回報可以倒轉的範圍至少 60 秒的直播。
- **直播最新位置：** 可回放範圍的最後一刻。目前位置距離直播最新位置 10 秒以內，視為「正在看直播」。
- **單格全螢幕：** 某一格放大到整個螢幕的狀態（R20）。這時「顯示中的來源」只有放大的那一格，其他來源都視為隱藏的來源（第一版共用定義）。
- **網址比對：** 清單中的「同一個網址」以去掉前後空白後的完整網址字串比對；同一部 YouTube 影片的不同寫法（例如 `youtu.be/…` 和 `youtube.com/watch?v=…`）視為不同網址。
- **影片名稱：** 加入清單時自動取得的名稱。YouTube 用影片標題；網頁來源用網頁標題；mp4 / m3u8 用網址最後一段的檔名。取不到時用網址。

## 4. 需求清單

### R19：進度條
- 描述：
  - 每格底部、操作按鈕上方多一條進度條，寬度是格子寬度減 12px，時間文字在進度條左側。進度條和操作按鈕一起在滑鼠停在格子上時顯示（第一版 R3 的顯示規則）；拖曳進度條時操作區不隱藏。
  - 點擊、拖曳進度條不影響聲音（不觸發 R7 的獨占聲音）。
  - 一般影片（有固定長度）：進度條代表整部影片，旁邊顯示「目前時間／總長度」，格式是 `m:ss`，一小時以上是 `h:mm:ss`。
  - 可回放的直播：進度條代表可回放的範圍，最右邊是直播最新位置，旁邊顯示距離直播的時間（例如 `-1:23`），另有「回到直播」按鈕。正在看直播時，按鈕顯示為「● LIVE」並停用。
  - 不能回放的直播：沒有進度條，只顯示「● LIVE」標記。
  - 點擊進度條或拖曳後放開，跳到那個位置；拖曳過程中顯示游標位置的時間，放開才跳。跳轉後維持原本的播放或暫停狀態；已經播完的影片跳轉後維持暫停。
  - 適用 YouTube、mp4、m3u8、網頁來源（作用在 R13 的主要影片）。網頁來源在影片模式和整頁模式都顯示；還沒找到主要影片時不顯示進度條。
  - 錯誤狀態、載入中還不知道長度時不顯示進度條。
  - 格子寬度小於 360px 時，不顯示時間文字，只顯示進度條（和 R14 AC7 的圖示模式一致），而且進度條移到操作按鈕下方（格子最底部）：最小的格子中操作區有三列高，進度條在上方會落在視窗頂端 40px 內，被工具列蓋住。
- 驗收條件：
  - AC1：播放一部 mp4（或 m3u8 點播影片）→ 滑鼠移到格子上 → 看到進度條和「目前時間／總長度」，時間隨播放前進。
  - AC2：在進度條中間點一下 → 跳到影片約一半的位置，播放中的維持播放、暫停中的維持暫停。
  - AC3：拖曳進度條 → 拖曳中顯示游標位置的時間，影片還沒跳轉；放開後才跳轉。
  - AC4：YouTube 一般影片 → 同 AC1–AC3。
  - AC5：可回放的 YouTube 直播 → 進度條最右邊是直播最新位置；往回拖 → 顯示距離直播的時間，「回到直播」按鈕可以按；按下後回到直播最新位置，按鈕變成「● LIVE」並停用。
  - AC6：不能回放的直播（例如沒有開放倒轉的 m3u8 直播）→ 只顯示「● LIVE」，沒有進度條。
  - AC7：網頁來源的主要影片 → 進度條作用在主要影片（本機測試頁驗證）。
  - AC8：錯誤狀態的格子 → 沒有進度條。
  - AC9：把格子縮到最小寬度 → 進度條仍然顯示並可以操作，不顯示時間文字。
  - AC10：點擊另一格（沒有聲音）的進度條 → 只跳轉，聲音狀態不變。
  - AC11：mp4 播完後點進度條中間 → 跳到該位置並維持暫停。

### R20：單格全螢幕
- 描述：
  - 每格的操作按鈕多一個「全螢幕」按鈕（有來源的格子才有）。
  - 按下後：視窗進入全螢幕（已經是全螢幕就維持），這一格填滿整個畫面；其他顯示中的來源暫停。分隔線和「移動」按鈕不顯示。
  - 離開：按這一格的「離開全螢幕」按鈕、按 Esc 或 F11 → 回到原本的分割畫面；視窗回到進入前的狀態（進入前不是全螢幕就離開全螢幕）。只有「進入時顯示中、而且正在播放」的其他來源恢復播放；原本暫停的、版型外的隱藏來源都維持暫停。
  - 焦點在整頁模式的網頁中時，Esc 依第二版 R14 交給網頁；這時用 F11 或按鈕離開。
  - 進入和離開時都不顯示第一版 R4 AC4 的「有 N 個來源暫時隱藏」提示。
  - 單格全螢幕期間：
    - 聲音設定（靜音、音量）不變，點擊畫面仍然依 R7 獨占聲音。
    - 「全部播放／暫停」和 Space 只作用在放大的那一格（共用定義：顯示中的來源只有這一格）。
    - 數字鍵 1–9 不作用。
    - 工具列照常可以叫出；按版型按鈕會先離開單格全螢幕，再切換版型。
    - 在這一格按「移除」或「更換網址」：移除時離開單格全螢幕；更換網址時留在單格全螢幕，播放新的網址。
  - 單格全螢幕不保存，重新開啟程式時是一般的分割畫面。
- 驗收條件：
  - AC1：`2×2` 四格都在播放，按第 2 格的「全螢幕」→ 視窗變成全螢幕，只看得到第 2 格的影片；第 1、3、4 格暫停。
  - AC2：接著按 Esc → 回到 `2×2`，視窗離開全螢幕；第 1、3、4 格恢復播放。
  - AC3：進入前第 3 格是暫停的 → 離開後第 3 格維持暫停。
  - AC4：先按 F11 讓視窗全螢幕，再進入單格全螢幕，然後按「離開全螢幕」按鈕 → 回到分割畫面，視窗維持全螢幕。
  - AC5：單格全螢幕時按 Space → 只有放大的那一格切換播放／暫停；按數字鍵 3 → 沒有變化。
  - AC6：單格全螢幕時按工具列的 `3×3` → 先回到分割畫面，再切換成 `3×3`。
  - AC7：單格全螢幕時按「移除」→ 回到分割畫面，那一格變成空白。
  - AC8：單格全螢幕中的影片不重新載入（直播不中斷）。
  - AC9：`2×2` 且第 5 格有隱藏的來源，進入再離開單格全螢幕 → 第 5 格維持暫停、隱藏；過程中不出現「有 N 個來源暫時隱藏」提示。
  - AC10：放大的是整頁模式的網頁來源，焦點在網頁輸入框中按 Esc → 留在單格全螢幕；按 F11 → 離開。

### R21：清單面板
- 描述：
  - 工具列多一個「清單」按鈕，按下後在視窗右側打開清單面板（寬 320px，蓋在影片上方，視窗寬度不到 640px 時佔滿整個寬度），再按一次或按面板的「✕」關閉。面板開著時工具列不會自動隱藏。
  - 面板有「最愛」「歷史」兩個分頁。每一筆顯示名稱、網址；歷史另外顯示最後播放的時間。
  - 放進格子：
    - 點一下某一筆 → 放進第一個顯示中的空格（依格子編號）。沒有空格時顯示「沒有空格，請拖到要更換的格子」，3 秒後消失。
    - 把某一筆拖到任一格放開 → 空格就放入；有影片的格子就更換網址（和第一版 R2 AC8 一樣，保留靜音和音量）。放開在格子以外的地方不做任何事。
    - 網址不支援時（例如改成了不支援的網址），顯示「不支援的網址」，格子不變。
  - 被面板蓋住的格子部分不能放下；面板佔滿整個寬度時只能用「點一下」放入。
  - 每一筆有「編輯」和「刪除」按鈕。一次只能編輯一筆，開始編輯另一筆時，前一筆的修改會被放棄。編輯時可以改名稱和網址，按「儲存」或 Enter 儲存，按「取消」或 Esc 放棄。
    - 網址必須是程式支援的網址（同第一版 R2、R12 的規則），否則顯示「不支援的網址」，不儲存。
    - 名稱清空時用網址當名稱。
    - 改成同一個清單中已經有的網址時，顯示「清單中已經有這個網址」，不儲存。
  - 刪除單筆不需要確認。
  - 在面板的輸入框中打字時，快捷鍵不作用（和網址輸入框相同）。
  - 最愛和歷史存在 `%APPDATA%\MultiView\lists.json`，和設定檔分開。檔案損毀時程式照常開啟，清單是空的，壞掉的檔案改名成 `lists.json.bak` 保留。變更後 1 秒內寫入。
- 驗收條件：
  - AC1：按「清單」→ 右側出現面板，有「最愛」「歷史」分頁；再按一次 → 面板關閉。
  - AC2：`2×2` 第 1、2 格有影片，點一下最愛中的一筆 → 放進第 3 格。
  - AC3：四格都有影片，點一下某一筆 → 顯示「沒有空格，請拖到要更換的格子」，格子都不變。
  - AC4：把某一筆拖到第 1 格（有影片、取消靜音、音量 40）→ 第 1 格改播這一筆，維持取消靜音、音量 40。
  - AC5：拖到格子以外放開 → 沒有變化。
  - AC6：編輯一筆，把網址改成 `ftp://x` 按儲存 → 顯示「不支援的網址」，內容不變；改成有效網址並把名稱清空後儲存 → 名稱變成網址。
  - AC7：編輯時把網址改成清單中另一筆的網址 → 顯示「清單中已經有這個網址」，不儲存。
  - AC8：按某一筆的「刪除」→ 那一筆消失。
  - AC9：在編輯框中按 Space、M、數字鍵 → 只輸入文字。
  - AC10：關閉程式再開啟 → 最愛和歷史都還在。
  - AC11：`lists.json` 內容損毀 → 程式照常開啟，清單是空的，壞掉的檔案被改名成 `lists.json.bak`。

### R22：最愛清單
- 描述：
  - 每格的操作按鈕多一個星號按鈕。這一格的網址不在最愛中時顯示「☆」（加入最愛），按下後以影片名稱加入最愛；已經在最愛中時顯示「★」，按下後從最愛移除。
  - 面板的「最愛」分頁上方有「新增」：輸入網址和名稱（名稱可以空白）加入，規則同 R21 的編輯（網址重複時顯示「清單中已經有這個網址」）。
  - 最新加入的排在最上面，沒有數量上限。
- 驗收條件：
  - AC1：在播放 YouTube 的格子按「☆」→ 按鈕變成「★」，最愛清單最上面多一筆，名稱是影片標題。
  - AC2：再按「★」→ 按鈕變回「☆」，那一筆從最愛移除。
  - AC3：另一格放同一個網址 → 那一格的按鈕也是「★」。
  - AC4：在「最愛」分頁按「新增」，輸入有效網址、名稱空白 → 加入一筆，名稱是網址。
  - AC5：從最愛刪除某一筆 → 播放這個網址的格子，按鈕變回「☆」。
  - AC6：「新增」一個已經在最愛中的網址 → 顯示「清單中已經有這個網址」，不新增。

### R23：歷史紀錄
- 描述：
  - 使用者放入格子的影片（在網址輸入框貼上、從清單放入、更換網址、重試）第一次成功載入時記一筆：YouTube 播放器就緒、mp4 / m3u8 可以播放、網頁來源「網頁載入完成」（第二版共用定義）。開啟程式時自動還原的來源、切換廣告阻擋造成的重新載入都不記錄。
  - 最後播放時間的格式是 `YYYY/MM/DD HH:mm`。
  - 同一個網址已經在歷史中時，不新增，改成更新最後播放時間並移到最上面；名稱維持原本的（使用者改過的名稱不會被蓋掉）。
  - 最多 200 筆，超過時刪掉最舊的。
  - 依最後播放時間排序，最新的在最上面。
  - 「歷史」分頁上方有「全部清除」，按下後出現確認視窗「確定要清除全部歷史紀錄？」，按「清除」才清除。
- 驗收條件：
  - AC1：在空白格貼上 YouTube 網址 → 載入後歷史最上面多一筆，名稱是影片標題，時間是現在。
  - AC2：再貼一次同一個網址（另一格）→ 歷史筆數不變，那一筆移到最上面、時間更新。
  - AC3：把歷史中某一筆改名後，再播放同一個網址 → 名稱維持改過的名稱。
  - AC4：網址無法載入（錯誤狀態）→ 不記錄。
  - AC5：關閉程式再開啟（自動還原 4 個來源）→ 歷史不變。
  - AC6：已經有 200 筆時播放新網址 → 新增一筆，最舊的一筆被刪掉，總數維持 200。
  - AC7：按「全部清除」→ 出現確認視窗；按「取消」→ 不變；按「清除」→ 歷史變空。

### R24：畫質
- 描述：
  - YouTube 和 m3u8 格子的操作按鈕多一個畫質按鈕，在「畫質：自動」和「畫質：高」之間切換。mp4 和網頁來源沒有這個按鈕。
  - **自動**（預設）：和現在相同，由播放器依格子大小和網路速度決定。
  - **高**：
    - YouTube：播放器以至少 1920×1080 的大小載入，再縮小顯示在格子裡，讓 YouTube 可以選到 1080p（影片本身有提供、網路速度足夠時）。YouTube 仍然可能依網路速度降低畫質，程式無法強制。
    - m3u8：固定使用最高的畫質，不隨網路速度自動降低（網路不夠快時可能卡頓）。
  - 切換時不重新載入影片（YouTube 調整畫質時可能短暫緩衝）。
  - 設定跟著來源：換位時一起移動，保存在設定檔（第一版 R10）。第一版、第二版的設定檔沒有這個欄位時視為「自動」。
  - 畫面上顯示的影片大小、比例和現在相同，只有畫質不同。YouTube 的「高」會讓播放器上的 YouTube 標誌和文字跟著縮小，這是預期的結果。
- 驗收條件：
  - AC1：`3×3` 版型的 YouTube 格子（影片有 1080p）在「自動」時畫質低於 720p；切換成「高」→ 網路足夠時 30 秒內提升到 1080p（從播放器回報的畫質確認），影片沒有重新從頭播放。
  - AC2：m3u8 格子（有多種畫質）切換成「高」→ 改用最高畫質；切回「自動」→ 恢復自動選擇。
  - AC3：mp4 和網頁來源的格子沒有畫質按鈕。
  - AC4：設成「高」後關閉程式再開啟 → 仍然是「高」；和另一格換位 → 設定跟著影片移動。
  - AC5：舊版的設定檔 → 讀取後所有格子都是「自動」。

### R25：版本號
- 描述：程式版本號從 0.1.0 更新為 0.2.0（包含第二版網頁來源與本規格的功能）。
- 驗收條件：
  - AC1：執行 `npm run dist` → 產生 `release/MultiView-0.2.0-portable.exe`。
  - AC2：exe 的檔案內容（右鍵 → 內容 → 詳細資料）顯示版本 0.2.0。

## 5. 對前置規格的影響

| 前置需求 | 變更 |
|---|---|

## 8. 非功能需求

- **效能：** 「畫質：高」會增加網路和電腦負擔；在 `2×2` 四格都設成「高」的 YouTube 1080p 直播連續播放 30 分鐘，程式不當掉、畫面不凍結（只能手動驗收）。
- **技術風險（實作時處理，不影響需求）：**
  - YouTube IFrame API 沒有公開「是不是直播」和「可回放範圍」的介面。實作使用播放器回報給頁面、但沒有公開文件的欄位（影片資訊的 `isLive`、`allowLiveDvr` 和播放狀態的 `progressState`）；直播的 `getDuration` 和 `getCurrentTime` 不同步，不能用來計算。YouTube 改版拿掉這些欄位時，直播會退回只顯示「● LIVE」。
  - YouTube 指定畫質的介面已經停用，「高」只能靠放大播放器尺寸；如果 YouTube 不因此提高畫質，要停下來回報。
  - 網頁來源的跳轉要透過注入網頁的程式控制主要影片。
- **測試：** 時間格式、可回放判斷、清單的新增／編輯／去重／上限、設定檔相容寫成單元測試；需要真實播放器的驗收條件以手動驗收（本機測試頁＋實際的 YouTube 影片）。
