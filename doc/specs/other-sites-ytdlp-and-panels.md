# 其他網站用 yt-dlp 播放、網頁讀取動畫、清單與小視窗改版 規格

- 功能代號：`other-sites-ytdlp-and-panels`
- Jira：無
- 狀態：已確認、已複查、已實作
- 最後更新：2026-11-06
- 前置規格：[ui-refresh-and-volume-boost](ui-refresh-and-volume-boost.md)（R96–R101）。本規格的需求編號從 R102 開始。

## 1. 背景與目標

2026-11-06 使用者試用 0.7.1 後：

1. 清單面板與 YouTube 小視窗的介面也要調整，尤其是小視窗的捲軸（小視窗裡的 YouTube 網頁用的是系統預設的淺色粗捲軸）。
2. 新功能（讀取動畫、畫質、語音、音量 200%）目前只有 YouTube 有；其他網站是整個網頁放在格子裡，沒有這些功能。希望其他網站也能用 yt-dlp。

使用者選擇（2026-11-06）：
- 其他網站：設定可選「網頁｜yt-dlp」，預設網頁；yt-dlp 播不了時退回網頁並提示（和 YouTube 的做法一致，R88–R90）。
- 用網頁播放的其他網站：影片模式下也顯示讀取動畫，整頁模式不顯示。
- 清單面板、小視窗改成和設定視窗（R96）同一個風格；捲軸改成深色細捲軸，小視窗裡 YouTube 網頁的捲軸也一樣。
- 工具列的「YouTube 小視窗」按鈕改成 YouTube 的紅色標誌樣式，比較好認。

## 2. 範圍

**包含：**
- 設定「其他網站的播放方式」（R102）
- 其他網站用 yt-dlp 播放與退回網頁（R103）
- 網頁播放的讀取動畫（R104）
- 清單面板改版（R105）
- YouTube 小視窗改版與捲軸（R106）
- 工具列小視窗按鈕的圖示（R107）
- 版本號（R108）

**不包含：**
- 需要登入、有版權保護（DRM，例如 Netflix）的網站用 yt-dlp 播放
- 只有影像、聲音分開格式的網站用 yt-dlp 播放（例如部分 Bilibili 影片；程式的播放器不能合併影音），這些會退回網頁
- YouTube 網站頁面（在格子裡逛 YouTube，R57）、YouTube 網頁播放（R48）：維持網頁
- 本機檔案、下載（R34–R39）

## 3. 共用定義

- **其他網站：** 網頁來源（第二版 R12），而且不是 YouTube 的網址（R57 的 YouTube 網站頁面、R48 的 YouTube 網頁播放都不算）。
- **網頁播放：** 現在的做法，整個網頁放在格子裡，有影片模式／整頁模式（第二版 R13、R14）。
- **yt-dlp 播放（其他網站）：** 用 yt-dlp 解析網頁網址，取得影片串流，由程式自己的播放器播放（和 R89 相同的播放器）。

## 4. 需求清單

### R102：其他網站的播放方式
- 描述：
  - 設定視窗（R96）多一個分類「其他網站」，裡面一列「其他網站的播放方式」，兩段選擇「網頁｜yt-dlp」，說明「yt-dlp 支援上千個影音網站（例如 Twitch、Vimeo、新聞台），播放時可以選畫質、語音、音量 200%；不支援或需要登入的網站會自動改用網頁。」
  - 預設「網頁」（和現在相同）；保存在設定檔，舊的設定檔視為「網頁」。
  - 改變選擇時，畫面上其他網站的格子立刻依新的方式重新載入（和 R88 相同：原本的播放／暫停狀態保留；從網頁改成 yt-dlp 時沿用網頁上偵測到的播放位置，偵測不到時從頭開始）。
  - 例外：正在整頁模式（第二版 R14）的格子不重新載入（使用者正在操作網頁），之後更換網址或重開程式時才套用新的方式。
- 驗收條件：
  - AC1：設定視窗有「其他網站」分類，預設「網頁」。
  - AC2：改成 yt-dlp → 其他網站的格子重新載入並改用 yt-dlp；YouTube 的格子不受影響。
  - AC3：關閉再開啟程式 → 仍是 yt-dlp；用 0.7.1 的設定檔開啟 → 「網頁」。

### R103：其他網站用 yt-dlp 播放
- 描述：
  - 選 yt-dlp 時，放入其他網站的網址（貼上、清單、更換網址、開啟程式還原）→ 先解析（顯示讀取動畫與「解析中…」，R99）。
  - 解析成功、而且有程式能播的格式 → 用程式自己的播放器播放：
    - 優先 HLS 主清單（可以選畫質、語音）；沒有時用影音合一的格式中畫質最高的一個。
    - 直播、一般影片都可以；可以拖曳進度條（直播依網站提供的範圍）、記住觀看進度（R55）。
    - 畫質、語音（R95）、音量 200%（R98）、讀取動畫（R99）、預先緩衝的限制（R100）都和 YouTube 的 yt-dlp 播放相同。
    - 歷史與最愛的名稱用解析得到的影片名稱（R22、R23）；網址仍是原本的網頁網址。
    - 網站要求的請求標頭（例如 Referer、User-Agent）由程式補上；跨網站存取許可只補給程式畫面發出的請求（和 R89 相同的規則）。
    - 實作時發現（2026-11-06）：
      - 剛解析出來的串流網址前幾秒會被拒（Dailymotion 和 YouTube 一樣）：先確認可以讀取才開始播放（最多 10 秒）。
      - 串流請求不帶程式畫面的網址當 Referer（Dailymotion 看到會拒絕）；網站要求的 Referer 由 yt-dlp 提供。
      - 只選播放器能播的容器（mp4、m4v、webm、mov）；avi、ogv 等不選（archive.org 原本選到 avi 無法播放）。
      - 串流轉址到其他伺服器（archive.org）時仍然算程式畫面發出的請求；這些請求不帶登入資訊，跨網站存取許可用「*」。
  - 以下情況退回網頁播放，工具列提示「yt-dlp 無法播放這個網站，已改用網頁播放」（提示規則同 R90）：解析失敗（不支援、需要登入、網路錯誤……）、沒有程式能播的格式（例如只有影音分開的格式、DRM）、播放中斷且重試都失敗。退回只對這一格這一次有效，不寫進設定檔。
  - yt-dlp 播放時的操作區：沒有「影片模式／整頁模式」「廣告阻擋」「直接操作」「上一頁／下一頁」（沒有網頁）；多一個「改用網頁」按鈕，按下後這一格改用網頁播放（同退回，只對這一次有效）。
  - 一個網頁有多部影片時（yt-dlp 解析為清單），用第一部。
  - 解析的快取、排隊（同時最多 3 個）、太舊時自動更新（R89、R92）和 YouTube 共用。
- 驗收條件：
  - AC1：其他網站選 yt-dlp → 貼上 TED 或 Dailymotion 影片的網址 → 解析後用程式的播放器播放，畫質選單有多種畫質、音量可以到 200。（原本寫 Twitch、Vimeo：Vimeo 現在需要登入，2026-11-06 實測會退回網頁）
  - AC2：貼上 yt-dlp 不支援的網站（例如一般新聞文章頁）→ 提示「yt-dlp 無法播放這個網站，已改用網頁播放」，改用網頁播放。
  - AC3：AC1 的格子按「改用網頁」→ 改用網頁播放；關閉再開啟 → 又先用 yt-dlp。
  - AC4：AC1 的格子 → 歷史的名稱是影片名稱，網址是原本的網頁網址。
  - AC5：AC1 的格子 → 沒有「影片模式／整頁模式」「廣告阻擋」「直接操作」按鈕。
  - AC6：其他網站選「網頁」→ 和 0.7.1 完全相同，不執行 yt-dlp。

### R104：網頁播放的讀取動畫
- 描述：
  - 網頁播放的格子（其他網站、YouTube 網頁播放）在影片模式下，網頁載入中、而且還沒找到影片時，中央顯示讀取動畫與「載入中…」（R99 的小生物與規則：0.5 秒內完成不顯示）。
  - 找到影片、網頁第一次載入完成、出現錯誤、切到整頁模式時不顯示。
  - 網頁在背景（R63 保留的來源頁面）時不顯示。
  - 取代 R99「網頁來源不顯示」的規定（只在整頁模式不顯示）。
- 驗收條件：
  - AC1：貼上其他網站的網址（網頁播放）→ 影片模式下網頁載入時出現小生物與「載入中…」，找到影片或載入完成後消失。
  - AC2：切到整頁模式 → 不顯示。
  - AC3：網頁載入失敗 → 顯示錯誤訊息（R16），不顯示小生物。

## 8. 非功能需求

- **安全：** 主程序只接受 http、https 的網址交給 yt-dlp；不經過命令列殼層。補上的請求標頭只用在程式畫面發出、而且是解析出來的串流網址所在網站的請求。
- **效能：** 其他網站選「網頁」時不執行 yt-dlp。
- **測試：** 其他網站格式的選擇、請求標頭、設定檔相容寫成單元測試；網站實際播放與外觀以手動驗收（截圖）。
