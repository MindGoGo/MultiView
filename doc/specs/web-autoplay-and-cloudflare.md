- 功能代號：`web-autoplay-and-cloudflare`
- Jira：無
- 狀態：已確認、已複查、已實作
- 最後更新：2026-11-07
- 前置規格：[ytdlp-badge-and-site-fixes](ytdlp-badge-and-site-fixes.md)（R109–R112）。本規格的需求編號從 R113 開始。

## 1. 背景與目標

2026-11-07 使用者回報：影片網站 C 的外連網址（轉到影片網站 B）用網頁播放，按「只顯示影片」時顯示「找不到影片」；手動按網站的播放鈕之後，再按「只顯示影片」就可以。

調查（2026-11-07，只看 yt-dlp 的解析資訊）：
- yt-dlp 先遇到 Cloudflare 的機器人驗證（403）；加上「模擬瀏覽器」（`--extractor-args generic:impersonate`，內附的 yt-dlp 有需要的元件）後通過驗證，但 yt-dlp 不支援 影片網站 B（Unsupported URL），只能用網頁播放。
- 這個網站要等使用者按播放鈕才在網頁上產生影片；程式是依網頁上的影片找出主要影片（第二版 R13），按播放之前找不到。原本的設計是提示「無法直接播放，請按『直接操作』後按網站的播放鈕」。

使用者選擇（2026-11-07）：
- 網頁找不到影片時，程式自動試著按一次網站的播放鈕，找到影片就只顯示影片。
- yt-dlp 遇到 Cloudflare 的機器人驗證時，自動用模擬瀏覽器重試一次（對其他有 Cloudflare 保護、yt-dlp 支援的網站有幫助）。

## 2. 範圍

**包含：**
- 網頁找不到影片時自動按播放鈕（R113）
- yt-dlp 遇到 Cloudflare 時重試（R114）
- 版本號（R115）

**不包含：**
- yt-dlp 不支援的網站（例如 影片網站 B）改用 yt-dlp：不可行
- 整頁模式下自動按播放（使用者正在操作網頁）

## 3. 共用定義

- **播放鈕：** 網頁上「開始播放」的按鈕。依常見播放器的按鈕（video.js、JW Player、Plyr、Flowplayer、MediaElement、Clappr 等）、以及名稱或說明含「play」「播放」的按鈕判斷；只選看得見、在畫面內、大小至少 16×16 像素的。不選連結（`<a href>` 或在連結裡面的元素）：按下去網頁會換頁（常見於廣告）。
- **自動按播放：** 在網頁的每一層框架（包括跨網域的子框架）各自找播放鈕，按畫面中最大、最靠近中央的一個，按一次。

## 4. 需求清單

### R113：網頁找不到影片時自動按播放鈕
- 描述：
  - 以下兩種情況，程式自動按播放一次：
    1. 影片模式、網頁載入完成 3 秒後仍然找不到影片（在第二版 R13 AC4 的 15 秒自動切換整頁模式之前）。
    2. 按「只顯示影片」時找不到影片：先顯示「正在找影片…」，自動按播放後最多等 6 秒，找到影片就切到影片模式；仍然找不到才顯示「找不到影片」（第二版 R14）。
  - 同一次網頁載入，情況 1 只試一次；情況 2 每次按「只顯示影片」都試一次。
  - 自動按播放後網站開始播放；這一格原本是暫停的（例如開啟程式時還原的格子，第一版 R10），找到影片後照原本的規則暫停（第二版 R15）。
  - 網站因為按播放而想開新視窗（例如廣告）時，照原本的規則擋下，不開新視窗（第二版 R13）。
  - 找不到播放鈕時不做任何事，維持原本的提示與行為。
  - 之後才出現在網頁上的框架（例如廣告的 iframe）不會因為先前的自動按播放而被按（實作時補充）。
  - 背景的來源頁面（R63）、整頁模式時（情況 1）不自動按。
- 驗收條件：
  - AC1：要先按播放才產生影片的網頁（例如 影片網站 B 的影片頁；驗收時該網站維護中，改用手動測試網頁 `tests/manual/web-pages/click-to-play.html`、`click-to-play-frame.html`），影片模式下載入 → 幾秒內自動開始，只顯示影片，不切換成整頁模式。
  - AC2：AC1 的網頁在整頁模式按「只顯示影片」→ 顯示「正在找影片…」，之後只顯示影片。
  - AC3：真的沒有影片的網頁（例如 example.com）→ 照原本：15 秒後切換成整頁模式並提示；按「只顯示影片」→ 「正在找影片…」後顯示「找不到影片」。
  - AC4：已經找得到影片的網頁 → 不會多按播放鈕（行為和 0.8.1 相同）。

### R114：yt-dlp 遇到 Cloudflare 時重試
- 描述：
  - 解析其他網站（R103）失敗，而且錯誤是 Cloudflare 的機器人驗證（yt-dlp 的訊息含「Cloudflare anti-bot challenge」）→ 自動加上模擬瀏覽器（`--extractor-args generic:impersonate`）重試一次；仍然失敗就照原本退回網頁（R103）。
  - 重試計入同一次解析（畫面維持「解析中…」）；不算 yt-dlp 太舊（R92），不觸發更新。
  - YouTube（R89）不受影響。
- 驗收條件：
  - AC1：（單元測試）錯誤含「Cloudflare anti-bot challenge」→ 判斷為需要重試；其他錯誤不重試。
  - AC2：貼上 R113 AC1 的外連網址（yt-dlp 選項開啟）→ 重試後 yt-dlp 回報不支援，退回網頁，小標示「網頁（yt-dlp 無法播放）」；接著 R113 自動按播放。

### R115：版本號
- 描述：程式版本號從 0.8.1 更新為 0.8.2，並打包。
- 驗收條件：
  - AC1：`npm run dist` → 產生 `release/MultiView-Setup-0.8.2.exe`；「關於」顯示 0.8.2。

## 8. 非功能需求

- **安全：** 自動按播放只在網頁裡觸發點擊，不開新視窗、不下載檔案（沿用網頁來源的限制）。
- **測試：** 播放鈕的挑選、Cloudflare 錯誤的判斷寫成單元測試；實際網站以手動驗收（部分網站只確認播放狀態，不截圖內容）。
