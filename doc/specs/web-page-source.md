# 支援一般影片網頁 規格

- 功能代號：`web-page-source`
- Jira：無
- 狀態：已確認、已複查
- 最後更新：2026-10-08
- 前置規格：[multiview-player](multiview-player.md)（R1–R11）。本規格的需求編號從 R12 接續，沿用該規格的「共用定義」。

## 1. 背景與目標

第一版只能播放 YouTube 和直接的 mp4 / m3u8 連結。很多直播只放在網站自己的頁面上，例如 Twitch、新聞台官網，沒辦法直接取得影片網址。這一版讓使用者貼上任意影片網頁的網址：程式在格子裡載入整個網頁，自動找出頁面上的主要影片並放大填滿格子。找不到影片，或需要先登入、按播放時，可以切換成顯示整個網頁來操作。

## 2. 範圍

**包含：**
- 任意 http / https 影片網頁（以 Twitch 和一個新聞台官網的直播頁為驗收對象）
- 自動偵測主要影片並填滿格子（影片模式），以及可以直接操作網頁的整頁模式
- 網頁來源的聲音、音量、播放 / 暫停，規則和第一版相同
- 內建廣告阻擋，每一格可以各自關閉
- 保留網站的登入狀態與 cookie

**不包含：**
- 有 DRM 版權保護的影片（例如 Netflix、Disney+），Electron 本身無法播放
- 在同一個網頁的多個影片之間手動選擇（一律選面積最大的，見 R13）
- 手動裁切或縮放影片畫面
- 清除網站資料（登出、刪除 cookie）的按鈕
- 不同格子使用不同帳號登入同一個網站
- 執行時更新廣告阻擋清單、自訂阻擋規則
- 記住使用者在網頁中換頁後的網址（保存的一律是原本輸入的網址）
- 特定平台的功能，例如 Twitch 聊天室
- YouTube 的 Shorts、播放清單頁、頻道頁（維持第一版的不支援）
- 降回第一版：第一版的程式讀到新版設定檔時，會把網頁來源當成不合法而丟掉

## 3. 共用定義

- **網頁來源：** 依 R12 判斷為一般網頁的來源。第一版的 YouTube、mp4、m3u8 來源以下統稱「影片來源」。
- **主要影片：** 網頁（包括網頁內嵌的子框架）中，符合以下全部條件的影片元素裡，顯示面積最大的一個；面積相同時取在頁面中較前面的那一個：
  - 和網頁可視範圍有重疊，而且重疊部分的寬至少 200 CSS px、高至少 112 CSS px；
  - 元素本身和上層都沒有被隱藏（不是 `display: none`、`visibility: hidden`），不透明度大於 0。

  「顯示面積」只計算和可視範圍重疊的部分。子框架中的影片，以它在最上層網頁中的位置計算。
- **網頁載入完成：** 網頁的主文件觸發 load 事件。
- **播放意圖：** 每個網頁來源記住使用者希望它播放還是暫停。新加入的來源是「播放」，從設定檔還原的是「暫停」。以下操作會更新播放意圖：全部播放 / 全部暫停、Space、隱藏（變成暫停），以及使用者在整頁模式中直接按網站的播放 / 暫停。
- **影片模式 / 整頁模式：** 網頁來源的兩種顯示方式，見 R13、R14。

## 4. 需求清單

### R12：辨識一般網頁網址
- 描述：
  - 任何 http / https 網址，只要不符合第一版 R2 的 YouTube 或 mp4 / m3u8 格式，就判斷為網頁來源。
  - 例外：網域是 `youtube.com`、`youtu.be` 或它們的子網域，但不符合 R2 格式的網址（例如 Shorts、播放清單頁、頻道頁），仍然顯示「不支援的網址」。
  - 空白格的提示文字改成「貼上 YouTube、mp4、m3u8 或影片網頁的網址」。
  - 網頁來源和影片來源一樣存進設定檔（R10），保存網址、靜音狀態、音量和廣告阻擋開關（R17）。
- 驗收條件：
  - AC1：在空白格貼上 Twitch 頻道網址並按 Enter → 該格開始載入網頁。
  - AC2：貼上 `https://example.com` → 被接受並開始載入（找不到影片時依 R13 AC4 處理）。
  - AC3：貼上 YouTube Shorts 網址、`ftp://` 開頭的網址、沒有 `http(s)://` 的網址（例如 `twitch.tv/abc`）或非網址的文字 → 顯示「不支援的網址」。
  - AC4：第一版 R2 支援的 YouTube、mp4、m3u8 網址，判斷結果和第一版相同。
  - AC5：同一個網頁網址可以放在多格。
  - AC6：設定好網頁來源後關閉程式 → 重新開啟 → 網頁來源回到原本的格位，靜音、音量、廣告阻擋設定都和關閉前一樣。
  - AC7：第一版的設定檔（沒有網頁來源）→ 新版照樣能讀取，內容不變。

### R13：只顯示網頁中的影片（影片模式）
- 描述：
  - 網頁來源一開始是影片模式。影片模式下，網頁至少以 1280×720 CSS px 的大小排版（長寬比和格子相同），再整體縮小顯示在格子裡；格子本身比這個大時就不縮放。格子小時很多網站會改用窄版或手機版排版，影片會被縮到小於主要影片的門檻，所以不以格子大小排版。「主要影片」的尺寸和可視範圍都以這個排版大小計算。
  - 網頁載入後，程式持續尋找主要影片。找到後，主要影片填滿格子、維持原本的長寬比，多出的空間顯示黑色；網頁的其他內容（選單、聊天室、網站的播放控制列等）都不顯示。
  - 網頁換掉主要影片（例如廣告結束換成正片、網站內換頁），或出現更大的影片時，2 秒內改成顯示新的主要影片。
  - 主要影片消失、又找不到新的主要影片時，格子顯示黑色畫面，並繼續尋找 15 秒；15 秒後仍然找不到，就依 AC4 切換成整頁模式。
  - 自動切換成整頁模式之後，不會再自動切回影片模式，要由使用者按「只顯示影片」（R14）。
  - 影片模式下，格子上的點擊攔截層和第一版相同：點擊影片會獨占聲音（R7），不會傳到網頁；「直接操作」（R3）也適用於網頁來源。
- 驗收條件：
  - AC1：（手動驗收）貼上正在直播的 Twitch 頻道網址 → 10 秒內格子只顯示直播畫面，看不到聊天室、網站選單或網站的控制列。
  - AC2：（手動驗收）貼上新聞台官網的直播頁網址（實作時選定，網址記在第 10 節）→ 10 秒內格子只顯示直播畫面。
  - AC3：網頁中有兩個以上的影片 → 顯示主要影片（面積最大的那一個）；小於 200×112、被隱藏或完全在可視範圍外的影片不列入。
  - AC3-1：本機測試頁中，主要影片放在跨網域的子框架裡 → 格子只顯示那個影片。
  - AC3-2：本機測試頁在播放 3 秒後把影片換成另一個 → 2 秒內格子改成顯示新的影片。
  - AC3-3：本機測試頁在播放中移除影片、之後不再出現 → 格子顯示黑色畫面，15 秒後切換成整頁模式並顯示 AC4 的提示。
  - AC4：網頁載入完成後 15 秒內都找不到主要影片 → 自動切換成整頁模式（R14），並在格子上方顯示「找不到影片，可以在網頁中操作後按『只顯示影片』」，5 秒後消失。
  - AC5：拖曳分隔線、拖曳換位、切換版型 → 網頁不重新載入，直播不中斷（同 R4 AC2、R5 AC5、R6 AC1）。
  - AC6：在影片模式點擊格子 → 依 R7 獨占聲音，網頁不會收到點擊。
  - AC7：在 `3×3` 版型（格子約 426×239）放入一個頁面在窄版時會把影片縮得很小的直播頁（例如 Twitch 頻道頁）→ 仍然找得到主要影片並填滿格子；切換成整頁模式時，網頁以格子大小排版、不縮放（R14）。

### R14：整頁模式
- 描述：
  - 網頁來源的操作按鈕多一個切換按鈕：影片模式時顯示「顯示整個網頁」，整頁模式時顯示「只顯示影片」。
  - 整頁模式：以網頁本身的版面顯示在格子裡，網頁的可視範圍就是格子的大小，不縮放（格子比較小時，網站可能改用手機版的版面），可以捲動。拿掉點擊攔截層，使用者可以直接點擊、輸入、捲動（例如登入、關閉提示、按播放）。
  - 整頁模式中點擊網頁不會觸發獨占聲音；喇叭按鈕和音量滑桿照常作用。
  - 焦點在整頁模式的網頁中時，除了 F11（仍然切換全螢幕）以外，按鍵（包括 Esc）都交給網頁，快捷鍵（R9）不作用。點擊網頁以外的地方（其他格子、工具列）後快捷鍵恢復。
  - 顯示模式不保存：重新開啟程式時一律從影片模式開始。拖曳換位、切換版型不會改變模式；更換網址、重試、切換廣告阻擋之後回到影片模式。
  - 格子太窄、操作按鈕放不下一列時，按鈕換行顯示，不可以被截掉。
- 驗收條件：
  - AC1：在影片模式按「顯示整個網頁」→ 看得到網站的完整版面，可以點擊連結、在輸入框打字、捲動頁面。
  - AC2：在整頁模式按「只顯示影片」→ 重新尋找主要影片；找到就切回影片模式，找不到就留在整頁模式並顯示「找不到影片」，3 秒後消失。
  - AC3：在整頁模式中點擊網頁裡的連結 → 在同一格裡換頁；會開新視窗的連結被擋下，不開新視窗。設定檔中保存的網址仍然是原本輸入的網址。
  - AC4：在整頁模式的網頁輸入框中按 Space、M 或數字鍵 → 只輸入文字，不觸發快捷鍵。
  - AC5：在整頁模式點擊網頁後，再點擊另一個影片模式的格子 → 快捷鍵恢復作用。
  - AC6：焦點在整頁模式的網頁中時按 F11 → 切換全螢幕；按 Esc → 不離開全螢幕，交給網頁。
  - AC7：把格子縮到最小寬度（第一版 R5 AC2）→ 網頁來源的所有操作按鈕都看得到、按得到。

### R15：網頁來源的聲音與播放
- 描述：網頁來源的靜音、音量、獨占聲音、全部播放 / 暫停 / 靜音、隱藏時暫停、開啟時維持暫停，規則都和第一版 R4 AC3、R7、R8、R9、R10 AC1 相同，差別如下：
  - 靜音作用在整個網頁，包括主要影片以外的聲音（例如廣告）。
  - 音量、播放、暫停作用在主要影片。
  - 還沒找到主要影片時：靜音照常作用；播放、暫停不作用；音量在找到主要影片後套用。
  - 網頁換成新的主要影片時（R13），套用目前的音量，並依播放意圖決定播放或暫停。網站自己開始播放、但播放意圖是「暫停」時，要把它暫停。
  - Space 判斷「有沒有來源在播放」時，網頁來源以主要影片是否正在播放為準。
- 驗收條件：
  - AC1：兩格網頁來源、一格 YouTube，點擊其中一格網頁來源的影片區域 → 只有那一格有聲音。
  - AC2：把網頁來源的音量調到 30 → 主要影片的音量是 30%，其他格不受影響。
  - AC3：按「全部暫停」→ 網頁來源的主要影片暫停；按「全部播放」→ 重新播放。
  - AC4：切換版型讓網頁來源變成隱藏的來源 → 主要影片暫停；切回後維持暫停。
  - AC5：關閉程式時有網頁來源 → 重新開啟 → 即使網站會自動播放，主要影片在找到後 1 秒內暫停；按「全部播放」或 Space 才開始播放。
  - AC6：網頁來源靜音時，網頁中的廣告或其他影片也沒有聲音。
  - AC7：在整頁模式中直接按網站的暫停後切回影片模式 → 維持暫停，不會被程式重新播放。

### R16：網頁來源的錯誤情境
- 描述：
  - 網頁本身載入失敗（找不到網站、憑證錯誤、伺服器對主文件回應 4xx / 5xx、從開始載入算起 30 秒內還沒有「網頁載入完成」），或網頁的程序當掉 → 格子顯示「無法載入網頁」，並提供「重試」和「更換網址」按鈕。「重試」重新載入原本的網址。
  - 網頁來源不會自動重試（第一版 R2 AC7 的自動重試只適用於 mp4 / m3u8）；網頁載入成功後的斷線由網站自己處理。
  - 主要影片觸發加密媒體事件（`encrypted`，表示需要 DRM）→ 格子顯示「這個影片有版權保護，無法播放」，並提供「更換網址」按鈕。
  - 錯誤狀態的網頁來源，和第一版一樣不受「全部播放 / 暫停 / 靜音」影響，點擊也不影響聲音（R7、R8）。
  - 網頁中的圖片、廣告等子項目載入失敗不算錯誤。
- 驗收條件：
  - AC1：貼上不存在的網域（例如 `https://no-such-host.invalid`）→ 顯示「無法載入網頁」和「重試」。
  - AC2：貼上回應 404 的網址 → 顯示「無法載入網頁」。
  - AC3：在錯誤狀態按「重試」→ 重新載入同一個網址；成功時恢復成影片模式。
  - AC4：網頁的程序當掉 → 顯示「無法載入網頁」，其他格繼續播放。
  - AC5：本機測試頁中的影片觸發加密媒體事件 → 顯示「這個影片有版權保護，無法播放」。
  - AC6：本機測試頁的主文件超過 30 秒才回應 → 顯示「無法載入網頁」。
  - AC7：網頁中有圖片載入失敗（404）→ 不顯示錯誤，正常播放。

### R17：廣告阻擋
- 描述：
  - 網頁來源預設開啟廣告阻擋：擋下符合 EasyList 主清單（不含 EasyPrivacy 等其他清單，以打包當時的版本為準）的網路請求，並隱藏清單中列出的廣告元素。
  - 每個網頁來源的操作按鈕有「廣告阻擋：開 / 關」切換，只影響這一格。切換後這一格的網頁會重新載入。
  - 開關狀態跟著來源：拖曳換位時一起移動，並且保存在設定檔中（R12）。
  - YouTube、mp4、m3u8 來源不套用廣告阻擋，維持第一版「不遮蓋 YouTube 標誌和廣告」的合規要求。網頁中內嵌的 YouTube 播放器（`youtube.com`、`youtube-nocookie.com` 的框架）發出的請求和裡面的元素也不阻擋。
  - 廣告清單隨程式一起打包，不在執行時下載（沒有網路時也能用；要更新清單需要重新打包）。
  - 網頁要開新視窗（彈出視窗）一律擋下，和第一版相同，不受開關影響。
- 驗收條件：
  - AC1：廣告阻擋開啟 → 本機測試頁請求 `https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js`（EasyList 中的廣告網址）→ 請求被擋下；同一頁對一般網址的請求正常。
  - AC2：在其中一格關閉廣告阻擋 → 該格重新載入，請求不再被擋；其他格仍然擋下。
  - AC3：關閉廣告阻擋後關閉程式 → 重新開啟 → 該格仍然是關閉。
  - AC4：YouTube 來源的請求不經過廣告阻擋；網頁中內嵌的 YouTube 播放器框架發出的請求也不阻擋。
  - AC5：拔掉網路線開啟程式 → 廣告阻擋照樣啟用，不顯示錯誤。

### R18：保留登入狀態
- 描述：所有網頁來源共用同一份網站資料（cookie、登入狀態、網站設定），存在 `%APPDATA%\MultiView\` 底下，關閉程式後保留。這份資料和 YouTube 播放器使用的資料分開。
- 驗收條件：
  - AC1：（手動驗收）在整頁模式登入 Twitch 後關閉程式 → 重新開啟 → 該格仍然是登入狀態。
  - AC2：兩格放同一個網站，其中一格在網站設定 cookie → 另一格重新載入後讀得到同一個 cookie。
  - AC3：本機測試頁設定一個有效期限一天的 cookie 後關閉程式 → 重新開啟 → 測試頁讀得到這個 cookie。
  - AC4：網頁來源設定的 cookie，YouTube 播放器讀不到（資料分開）。

## 5. 對第一版需求的影響

| 第一版需求 | 變更 |
|---|---|
| 範圍「不包含」 | 移除「任意網頁中的影片」和「Twitch 和其他平台」 |
| R2 描述 | 提示文字改成 R12 的版本；支援格式加上網頁來源 |
| R2 AC4 | `https://example.com` 不再是「不支援的網址」，改成網頁來源；YouTube Shorts 和非網址文字維持不支援 |
| R3 | 「直接操作」也出現在網頁來源 |
| R9 AC2 | 加上「整頁模式的網頁中」也不觸發快捷鍵（R14 AC4） |
| R10 | 保存內容加上網頁來源的廣告阻擋開關 |

## 6. API 變更

無。這是獨立的桌面程式，沒有後端 API。

## 7. 資料表變更

無。設定檔（JSON）的來源多一種類型和一個廣告阻擋欄位，舊的設定檔照樣能讀取（R12 AC7）。

## 8. 非功能需求

- **安全：** 網頁在獨立的程序和沙箱中執行，不能使用 Node.js 或程式本身的功能，只能透過程式提供的固定介面回報影片狀態。
- **效能：** 在 `2×2` 版型同時播放 4 個 Twitch 直播 30 分鐘，程式不當掉、畫面不凍結（只能手動驗收）。
- **合規：** 不繞過 DRM；YouTube 來源不套用廣告阻擋。
- **技術選型（實作時處理，不影響需求）：**
  - 網頁用 Electron 的 `<webview>` 顯示，放在 DOM 中，第一版的點擊攔截層和操作按鈕才能蓋在上面。
  - 主要影片可能在跨網域的子框架中（例如新聞台內嵌別家的播放器），偵測程式要注入到所有框架，而且要讓上層框架把那個子框架一起放大。如果做不到，要停下來回報，不能自行放寬 R13。
  - 廣告阻擋要判斷請求來自哪一格（R17 每格各自開關）以及哪個框架（YouTube 框架不阻擋）。如果套件不支援，要停下來回報。
  - 廣告阻擋使用 `@ghostery/adblocker-electron`，在打包時把 EasyList 預先轉換好放進程式。
- **測試：** 網址判斷、主要影片的挑選規則、播放意圖、設定檔讀寫、錯誤分類寫成單元測試。用本機測試頁的驗收條件，因為第一版的端對端測試還沒完成（在 `wip/e2e-tests`），先附上測試頁和操作步驟手動驗證；標示「手動驗收」的需要真實網站。
