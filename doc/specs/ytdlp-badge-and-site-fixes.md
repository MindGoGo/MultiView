- 功能代號：`ytdlp-badge-and-site-fixes`
- Jira：無

- 最後更新：2026-11-07
- 前置規格：[other-sites-ytdlp-and-panels](other-sites-ytdlp-and-panels.md)（R102–R108）。本規格的需求編號從 R109 開始。

## 1. 背景與目標

2026-11-07 使用者試用 0.8.0 後回報：

1. 看不出一格是不是用 yt-dlp 播放，希望左上角有小標示（滑鼠移到格子上才顯示），YouTube 也要。
2. Twitch：讀取很久，進度條很怪（`-298261:36:55`），按「回到直播」會卡住，沒有畫質選項。
3. 影片網站 A：播出一段「禁止播放」的影片。
4. 經過轉址的網址（影片網站 C 的外連網址）跳回網頁播放，問能不能用 yt-dlp。

調查結果（2026-11-07，只看 yt-dlp 的解析資訊與網路請求，不看影片內容）：

- 第 2 項：截圖的格子是**網頁播放**（有「直接操作」「顯示整個網頁」「廣告阻擋」），是 yt-dlp 播放失敗後退回網頁；畫質選項、進度條的問題都是網頁播放的現象。yt-dlp 能解析 Twitch 直播（有主清單，160p–1080p60），失敗原因是 Twitch 的各畫質清單看到請求的 `Origin: http://127.0.0.1` 就回 403（curl 實測：不帶 Origin 或 Origin 是 twitch.tv 都是 200）。
- 第 3 項：影片網站 A 能解析出 240p–720p 的 mp4；影片伺服器看到 `Origin: http://127.0.0.1`（或 Referer 是 127.0.0.1）就轉址到一段「禁止播放」的替代影片（`na.mp4`）。0.8.0 已經不帶 Referer，但仍帶 Origin。
- 第 4 項：外連網址轉址到 影片網站 D，yt-dlp 回報「Unsupported URL」（不支援這個網站），退回網頁是正確的。順帶發現：程式把「Unsupported URL」當成 yt-dlp 太舊，每遇到不支援的網站就會自動更新一次 yt-dlp（有 10 分鐘的間隔），應該修正。

使用者選擇（2026-11-07）：小標示三種都標（yt-dlp、內嵌播放器、網頁），滑鼠移到格子上才顯示；版本 0.8.1。

## 2. 範圍

**包含：**
- 播放方式的小標示（R109）
- 其他網站串流請求的來源標頭修正（R110）
- 不支援的網站不觸發 yt-dlp 更新（R111）
- 版本號（R112）

**不包含：**
- 網頁播放 Twitch 時的進度條顯示與「回到直播」卡住（網頁播放的既有問題，第二版 R19；改用 yt-dlp 播放後不會遇到）。另外處理，見未決事項。
- yt-dlp 不支援的網站（例如 影片網站 D）：維持退回網頁。

## 3. 共用定義

- **播放方式：** YouTube 是內嵌播放器或 yt-dlp（R88）；其他網站是網頁或 yt-dlp（R102）。
- **程式畫面發出的串流請求：** R89、R103 的定義（請求的 Origin 是程式畫面的網址，包括轉址後的同一個請求）。

## 4. 需求清單

### R109：播放方式的小標示
- 描述：
  - YouTube 與其他網站的格子，滑鼠移到格子上（和操作區同時出現、同時隱藏）時，左上角顯示小標示：
    - 「yt-dlp」：用 yt-dlp 播放（R89、R103），綠色。
    - 「內嵌播放器」：YouTube 用內嵌播放器，灰色。
    - 「網頁」：其他網站用網頁播放、YouTube 網頁播放（R48）、YouTube 網站頁面（R57），灰色。
    - 從 yt-dlp 退回時（R90、R103）文字加上「（yt-dlp 無法播放）」，例如「網頁（yt-dlp 無法播放）」。
    - 解析中不顯示（中央已有讀取動畫，R99）。
  - 滑鼠移到小標示上時顯示說明，例如「用 yt-dlp 播放：可以選畫質、語音，音量可到 200%」「用網頁播放：yt-dlp 不支援這個網站或需要登入」。
  - mp4、m3u8 網址的格子不顯示（沒有可選的播放方式）。
  - 位置：左上角；有「有聲音」標示（🔊）時排在它的右邊。小標示本身可以讓滑鼠停留以顯示說明，點擊它沒有作用（不會切換聲音、不會播放／暫停）。
  - 格子太窄（寬度小於 180 像素）時只顯示短字「yt-dlp」「內嵌」「網頁」。
- 驗收條件：
  - AC1：用 yt-dlp 播放的 YouTube 格子，滑鼠移上去 → 左上角出現綠色「yt-dlp」；移開 → 隨操作區一起消失。
  - AC2：內嵌播放器的 YouTube 格子 → 「內嵌播放器」。
  - AC3：其他網站 yt-dlp 播放 → 「yt-dlp」；網頁播放 → 「網頁」；yt-dlp 失敗退回 → 「網頁（yt-dlp 無法播放）」。
  - AC4：mp4、m3u8 網址的格子 → 沒有小標示。
  - AC5：有聲音的格子 → 小標示在 🔊 的右邊，不重疊。

### R110：其他網站串流請求的來源標頭
- 描述：
  - 程式畫面發出的串流請求（R89、R103）：
    - 不帶 Origin（Twitch、影片網站 A 看到程式畫面的網址會拒絕或給替代影片）。仍然依原本的 Origin 判斷是不是程式畫面發出的請求，再拿掉。
    - 不帶 Sec-Fetch-*（實作時發現：拿掉 Origin、帶網頁網址當 Referer 後，影片網站 A 仍因 `Sec-Fetch-Site: cross-site` 給替代影片；curl 實測加上這個標頭就會轉到 `na.mp4`）。
    - 其他網站（R103）的串流：Referer 是原本的網頁網址（和瀏覽器在那個網頁播放時相同；yt-dlp 有提供 Referer 時用 yt-dlp 的）。YouTube 的串流不帶 Referer（維持 0.8.0）。
    - 補上的請求標頭（User-Agent、Referer）套用到串流所在網站的同一個網域（例如 `usher.ttvnw.net` 與 `aps12.playlist.ttvnw.net` 都是 `ttvnw.net`），不只是同一個主機。
- 驗收條件：
  - AC1：其他網站選 yt-dlp → 貼上正在直播的 Twitch 頻道 → 用程式的播放器播放，畫質選單有多種畫質，標示「yt-dlp」。
  - AC2：貼上 影片網站 A 影片 → 播放的是影片本身，不是「禁止播放」的替代影片（以網路請求確認沒有轉到 `na.mp4`）。
  - AC3：YouTube（yt-dlp）、TED、Dailymotion、archive.org 仍然正常播放（迴歸）。

### R111：不支援的網站不觸發 yt-dlp 更新
- 描述：yt-dlp 回報「Unsupported URL」（不支援這個網址）時，視為一般的失敗（退回網頁或內嵌，R90、R103），不當成 yt-dlp 太舊，不觸發自動更新（R92）。
- 驗收條件：
  - AC1：貼上 yt-dlp 不支援的網站 → 退回網頁，沒有執行 yt-dlp 更新。

### R112：版本號
- 描述：程式版本號從 0.8.0 更新為 0.8.1，並打包。
- 驗收條件：
  - AC1：`npm run dist` → 產生 `release/MultiView-Setup-0.8.1.exe`；「關於」顯示 0.8.1。
