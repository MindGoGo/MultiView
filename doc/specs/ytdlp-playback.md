# YouTube 可選用 yt-dlp 播放 規格

- 功能代號：`ytdlp-playback`
- Jira：無
- 狀態：已確認、已複查、已實作
- 最後更新：2026-11-06
- 前置規格：[companion-window-fixes](companion-window-fixes.md)（R84–R87）。本規格的需求編號從 R88 開始（R34–R39 保留給本機播放與下載）。
- 參考：使用者在另一台電腦整理的計畫 `ytdlp-playback.md`（2026-11-06）。與計畫不同之處見第 5 節。

## 1. 背景與目標

YouTube 現在用官方內嵌播放器播放，會有 YouTube 的廣告、標誌、片尾推薦，禁止嵌入的影片也不能直接播。yt-dlp 可以把 YouTube 網址換成實際的串流網址，交給程式自己的播放器（和 mp4、m3u8 相同）播放。

使用者選擇（2026-11-06）：
- 設定裡可以選擇 YouTube 的播放方式，直播和一般影片分開選，預設都是內嵌播放器（和現在相同）。
- yt-dlp 播不了時，這一格自動退回內嵌播放器，並在工具列提示。
- 設定裡顯示 yt-dlp 是不是最新版，有新版時可以點擊更新；另外保留計畫中的自動更新。
- 用 yt-dlp 播放時第一版不支援字幕。
- 接受用 yt-dlp 播放不符合 YouTube 服務條款，只供個人使用（計畫 D1）。
- 可行性測試已由使用者在另一台電腦完成，確認可行（計畫第 2 節）。

## 2. 範圍

**包含：**
- 設定選單的「YouTube 直播播放方式」「YouTube 一般影片播放方式」（R88）
- 用 yt-dlp 解析並播放 YouTube（R89）
- yt-dlp 失敗時退回內嵌播放器（R90）
- 內附 yt-dlp 並準備可執行的那一份（R91）
- yt-dlp 自動更新（R92）
- 設定選單顯示 yt-dlp 版本與更新（R93）
- 版本號（R94）

**不包含：**
- 用 yt-dlp 播放時的字幕
- 用 yt-dlp 播放一般影片時 360p 以上的畫質（YouTube 的高畫質影音分開，需要另外合併）
- 需要登入的影片用 yt-dlp 播放（會員限定、年齡限制；這些會退回內嵌，依現有規則處理）
- 每一格各自選擇播放方式（只有整個程式的設定）
- YouTube 網頁播放（R48）、整頁模式（R66）、一般網頁來源改用 yt-dlp
- yt-dlp 下載（R35–R39，另一份規格）
- MultiView 程式本身的自動更新
- 移除內嵌播放器（計畫第 4.6 節不做）

## 3. 共用定義

- **內嵌播放器：** 現在播放 YouTube 的方式（YouTube 官方內嵌播放器）。
- **yt-dlp 播放：** 由程式內附的 yt-dlp 把 YouTube 網址解析成串流網址，再用程式自己的播放器（和 mp4、m3u8 相同）播放。
- **解析：** 用 yt-dlp 把 YouTube 影片代碼換成串流網址的過程，結果包括「是不是直播」、串流網址、影片名稱、網址的有效期限。
- **YouTube 播放器格子：** 來源是 YouTube 網址、而且不是 YouTube 網頁播放（R48）或整頁模式（R66）的格子。
- **使用者的 yt-dlp：** `%APPDATA%\MultiView\bin\yt-dlp.exe`。程式實際執行、更新的都是這一份。
- **內附的 yt-dlp：** 安裝檔裡附帶的 yt-dlp，只用來複製成使用者的 yt-dlp。

## 4. 需求清單

### R88：設定選單的播放方式
- 描述：
  - 「⚙ 設定」選單（R49）新增兩組選項，每組選一個（目前的選擇打勾）：
    - 「YouTube 直播：內嵌播放器」「YouTube 直播：yt-dlp」
    - 「YouTube 一般影片：內嵌播放器」「YouTube 一般影片：yt-dlp（最高 360p）」
  - 兩組預設都是內嵌播放器。選擇保存在設定檔，關閉程式再開啟仍然保留；舊的設定檔沒有這兩個設定時視為內嵌播放器。
  - 決定一格用哪一種方式：
    - 兩組都是內嵌播放器 → 直接用內嵌播放器，不執行 yt-dlp（和現在完全相同）。
    - 任一組是 yt-dlp → 先解析，依解析結果是直播還是一般影片，套用那一組的選擇。結果那一組是內嵌播放器時，改用內嵌播放器播放（例如只有直播選 yt-dlp 時，一般影片要等解析完才開始用內嵌播放）。
    - 還沒開始的直播、首播：解析會失敗，依 R90 退回內嵌播放器（顯示 YouTube 的倒數畫面）。
  - 改變選擇時，畫面上所有受影響的 YouTube 播放器格子立刻用新的方式重新載入：
    - 受影響：目前播放方式和新的選擇不同的格子；因為 R90 退回內嵌、或正在顯示錯誤的格子也重新決定。
    - 一般影片從原本的時間點繼續；直播從最新的位置。
    - 原本在播放的繼續播放，原本暫停的維持暫停。
    - 音量、靜音、亮度、畫質的選擇保留。
  - YouTube 網頁播放（R48）、整頁模式（R66）的格子不受影響。
  - 改變選擇時正在「解析中…」的格子：取消這次的結果，依新的選擇重新決定（兩組都改成內嵌播放器時直接用內嵌播放）。
- 驗收條件：
  - AC1：全新的設定 → 打開「⚙ 設定」→ 兩組都勾選「內嵌播放器」；貼上 YouTube 網址 → 用內嵌播放器播放，看得到 YouTube 的介面。
  - AC2：把「YouTube 直播」改成 yt-dlp → 正在播放的直播格子重新載入，改成 yt-dlp 播放並繼續播放；一般影片的格子不變。
  - AC3：把「YouTube 一般影片」改成 yt-dlp → 暫停在 1:00 的一般影片格子重新載入，停在 1:00 並維持暫停。
  - AC4：AC2 之後關閉再開啟程式 → 設定仍是 yt-dlp，直播格子用 yt-dlp 播放。
  - AC5：用 0.6.1 的設定檔開啟 → 兩組都是內嵌播放器。
  - AC6：只有直播選 yt-dlp，貼上一般影片 → 格子先顯示「解析中…」，之後用內嵌播放器播放。
  - AC7：YouTube 網頁播放的格子 → 改變設定後不重新載入。

### R89：用 yt-dlp 播放
- 描述：
  - 解析中格子中央顯示「解析中…」（半透明，不擋操作按鈕）。
  - 直播：用 HLS 的主清單播放，畫質選單列出主清單裡的畫質，「自動」依格子大小和網路速度選擇（沿用 m3u8 的做法，R24、R32）。
  - 一般影片：用影音合一的 360p mp4 播放；畫質按鈕停用，滑鼠移上去顯示「yt-dlp 播放一般影片固定 360p」。保存的畫質選擇不改變（切回內嵌播放器時照用）。
  - 字幕按鈕停用，滑鼠移上去顯示「yt-dlp 播放方式不支援字幕」。保存的字幕選擇不改變。
  - 格子裡只有影片畫面，沒有 YouTube 的控制列、標誌、廣告、推薦影片。
  - 沒有「直接操作播放器」按鈕（第一版 R3；和 mp4、m3u8 相同，沒有可以直接操作的 YouTube 介面）。用內嵌播放器的格子照舊有這個按鈕。
  - 影片名稱（歷史、最愛的名稱，R22、R23）用解析拿到的名稱。
  - 和內嵌播放器相同、照常可用：播放／暫停、音量、靜音、亮度、進度條與拖曳、預覽縮圖（R50）、快轉倒轉（R51）、記住觀看進度（R55）、「YouTube ▾」選單（R66）、YouTube 小視窗（R78）、一般影片播完停在最後一格（R2 AC3）。
  - 網址過期與斷線：
    - 播放中載入失敗（網址過期、斷線）→ 重新解析（不使用快取）後繼續播放；重新解析計入 R2 AC7 的 3 次重試。
    - 暫停到超過網址有效期限前 1 分鐘之後才按播放 → 先重新解析再播放；一般影片從原本的時間點繼續。
  - 解析的資源限制：
    - 同一部影片的解析結果快取到網址有效期限前 10 分鐘。
    - 同一部影片同時被多格要求時只解析一次。
    - 同時最多執行 3 個 yt-dlp，其餘排隊（開啟程式還原 9 格時不會一次執行 9 個）。
    - 關閉程式時結束還在執行的 yt-dlp。
  - 串流的網址由程式取得，要能在格子裡播放（必要時由程式補上跨網站存取的許可）。
  - 剛解析出來的一般影片網址，前幾秒 YouTube 會拒絕（2026-11-06 實測約 3 秒）：確認網址可以讀取後才開始播放，最多等 10 秒，這段時間仍然顯示「解析中…」（實作時發現）。
- 驗收條件：
  - AC1：直播選 yt-dlp → 貼上 YouTube 直播網址 → 顯示「解析中…」，10 秒內開始播放，格子裡看不到任何 YouTube 介面。
  - AC2：AC1 的格子打開畫質選單 → 列出多種畫質；選 480 → 改用 480。
  - AC3：一般影片選 yt-dlp → 貼上一般影片 → 播放 360p；畫質、字幕按鈕停用並有說明；播完停在最後一格。
  - AC4：AC3 的格子 → 拖曳進度條、快轉倒轉、預覽縮圖、「YouTube ▾」選單、小視窗都可以使用；歷史的名稱是影片名稱。
  - AC5：yt-dlp 播放中關掉網路 30 秒再接回 → 自動恢復播放。
  - AC6：暫停一般影片，等到超過網址有效期限（測試時把期限改短）→ 按播放 → 從原時間點繼續播放。
  - AC7：同一部直播放在 2 格 → 只執行一次 yt-dlp。
  - AC8：9 格都是 YouTube，開啟程式 → 同時執行的 yt-dlp 不超過 3 個，9 格都解析完成並依 R10 維持暫停。
  - AC9：版型切換、換位（R4 AC2、R6 AC1）→ yt-dlp 播放的格子不中斷、不重新解析。

### R90：yt-dlp 失敗時退回內嵌播放器
- 描述：
  - 以下任何一種情況，這一格改用內嵌播放器播放：
    - 解析失敗，任何原因都算（影片不存在、私人、需要登入、還沒開始的直播、yt-dlp 太舊而自動更新後仍然失敗、找不到 yt-dlp、逾時、網路錯誤……）。
    - 播放中斷，3 次重試（含重新解析）都失敗。
    - 解析成功但沒有可以播的格式。
  - 退回時工具列提示「yt-dlp 無法播放，已改用內嵌播放器」（現有的提示樣式）。提示還在顯示時又有格子退回，不重複提示，提示時間也不延長。
  - 退回時一般影片從原本的時間點繼續，原本的播放／暫停狀態保留。
  - 退回之後就是一般的內嵌播放器：內嵌也不能播時照現有規則處理（禁止嵌入依 R49 的設定改用網頁播放或顯示 R48 的錯誤；其他錯誤顯示原本的訊息）。
  - 退回只對這一格的這一次有效，不寫進設定檔：重新開啟程式、按「重試」、更換網址、改變 R88 的設定時，都重新依 R88 決定。
  - 解析在 R92 的自動更新期間排隊等待時，不算失敗。
- 驗收條件：
  - AC1：兩組都選 yt-dlp → 貼上已刪除的影片 → 顯示「解析中…」，之後提示「yt-dlp 無法播放，已改用內嵌播放器」，格子顯示內嵌播放器的錯誤。
  - AC2：兩組都選 yt-dlp → 貼上還沒開始的直播 → 退回內嵌播放器，看得到 YouTube 的倒數畫面。
  - AC3：兩組都選 yt-dlp、勾選 R49 自動改用網頁播放 → 貼上 yt-dlp 不能解析、而且禁止嵌入的影片 → 退回內嵌，再自動改成網頁播放。
  - AC4：把使用者的 yt-dlp 換成無法執行的檔案、內附的也拿掉（模擬 R91 AC4）→ 貼上 YouTube → 退回內嵌並提示；mp4、m3u8 不受影響。
  - AC5：AC1 的格子關閉再開啟程式 → 重新先用 yt-dlp 解析。
  - AC6：yt-dlp 播放中斷，重試 3 次都失敗 → 一般影片從原本的時間點改用內嵌播放器繼續。

### R91：內附 yt-dlp
- 描述：
  - 安裝檔附帶一份 yt-dlp，沒有安裝 Python 或 yt-dlp 的電腦也能使用。
  - 開啟程式時：
    - 使用者的 yt-dlp 不存在或無法執行 → 從內附的複製一份。
    - 程式本身換了版本（和上次開啟時不同）時，比較兩份 yt-dlp 的版本號，內附的比較新就覆蓋使用者的。程式版本沒變時不比較，不拖慢開啟。
    - 這些都在背景進行，不延遲視窗顯示；完成前送出的解析會排隊等候。
  - 複製失敗時沒有可用的 yt-dlp：所有解析都視為失敗，依 R90 退回內嵌播放器；設定選單顯示「找不到 yt-dlp」（R93）。
- 驗收條件：
  - AC1：在沒裝任何開發工具的電腦安裝後開啟 → `%APPDATA%\MultiView\bin\yt-dlp.exe` 存在；直播選 yt-dlp 後可以播放。
  - AC2：刪除使用者的 yt-dlp 再開啟程式 → 自動複製回來。
  - AC3：使用者的 yt-dlp 比內附的舊，並把記錄的程式版本改掉 → 開啟時被內附的覆蓋。
  - AC4：使用者的 yt-dlp 不存在，而且複製失敗 → YouTube 退回內嵌（R90 AC4），設定選單顯示「找不到 yt-dlp」。

### R92：yt-dlp 自動更新
- 描述：
  - 更新的是使用者的 yt-dlp，用 yt-dlp 本身的更新功能，更新到最新的穩定版（stable）。更新失敗時保留原本那一份，播放不受影響。
  - 自動更新的時機：
    1. 開啟程式時，距離上次檢查超過 24 小時 → 視窗顯示後在背景更新，不顯示任何訊息；24 小時內再開啟不重複。
    2. 解析失敗，而且錯誤看起來是 yt-dlp 太舊（無法解析 YouTube 頁面）→ 格子維持「解析中…」，自動更新後重新解析一次。更新後成功就直接播放；已經是最新版、更新失敗或更新後仍然失敗 → 依 R90 退回內嵌。
  - 時機 2 的限制：同一次失敗只自動更新一次；多格同時失敗只更新一次，更新完各自重新解析；自動更新之後 10 分鐘內再遇到太舊的錯誤，不再自動更新，直接退回內嵌。
  - 同一時間只進行一個更新：開啟時的更新、失敗時的更新、R93 的手動更新同時發生時共用同一次。
  - 更新開始時，新的解析排隊等更新結束（成功或失敗都一樣）才開始；正在執行的解析不中斷，更新等它們結束後才開始（避免檔案被占用）。
  - 上次檢查的時間、上次開啟時的程式版本（R91 用）記錄在 `%APPDATA%\MultiView\bin\update.json`（不放在設定檔）；讀不到或格式錯誤時當作從來沒檢查過、程式版本不同。
  - 自動更新的結果不顯示提示，但設定選單（R93）的狀態會跟著更新。
- 驗收條件：
  - AC1：把使用者的 yt-dlp 換成舊版、刪除 `update.json` 後開啟 → 開啟速度不變，過一會兒使用者的 yt-dlp 變成最新版；馬上再開一次 → 不重複更新。
  - AC2：換成舊到無法解析 YouTube 的版本，把上次檢查時間改成現在，直播選 yt-dlp 後貼上直播 → 維持「解析中…」，之後直接開始用 yt-dlp 播放，使用者的 yt-dlp 變成最新版。
  - AC3：AC2 的情況下 3 格同時解析失敗 → 只更新一次，3 格都重新解析後播放。
  - AC4：AC2 的情況下沒有網路 → 退回內嵌（內嵌也因沒有網路而顯示原本的錯誤），原本的 yt-dlp 還在。
  - AC5：更新進行中貼上 YouTube 網址 → 顯示「解析中…」，更新完成後才開始解析。

### R93：設定選單的 yt-dlp 版本與更新
- 描述：
  - 「⚙ 設定」選單在 R88 的選項下面、版本號（R76）上面，多一行 yt-dlp 的狀態：

    | 狀態 | 顯示 | 可以點擊 |
    |---|---|---|
    | 是最新版 | 「yt-dlp <版本>（已是最新版）」 | 否 |
    | 有新版 | 「yt-dlp <版本>：有新版 <新版本>，點這裡更新」 | 是 |
    | 正在檢查 | 「yt-dlp <版本>（正在檢查更新…）」 | 否 |
    | 檢查失敗 | 「yt-dlp <版本>（無法檢查更新）」 | 是，點了直接嘗試更新 |
    | 正在更新（含自動更新） | 「yt-dlp 正在更新…」 | 否 |
    | 找不到 yt-dlp（R91 AC4） | 「找不到 yt-dlp」 | 否 |

  - 是否有新版：向 GitHub 查詢 yt-dlp 最新穩定版的版本號，和使用者的 yt-dlp 比較。查詢時機是開啟程式時、和打開設定選單時，距離上次查詢不到 1 小時就沿用上次的結果。
  - 選單開著時狀態改變（查詢完成、更新完成）會即時更新顯示。
  - 點擊更新：執行 R92 的更新（共用同一次）。點擊後選單不關閉，狀態改成「正在更新…」；完成後工具列提示結果：
    - 「yt-dlp 已更新到 <版本>」
    - 「yt-dlp 已經是最新版」
    - 「yt-dlp 更新失敗」（沒有網路、GitHub 連不上、檔案檢查不符）
  - 更新成功後，因為 R90 退回內嵌的格子不自動改變（使用者可以按「重試」或改變設定）。
- 驗收條件：
  - AC1：使用者的 yt-dlp 是最新版 → 打開設定 → 顯示「yt-dlp <版本>（已是最新版）」，無法點擊。
  - AC2：換成舊版後打開設定 → 顯示「有新版 …，點這裡更新」；點擊 → 顯示「正在更新…」，完成後提示「yt-dlp 已更新到 <版本>」，該行變成「已是最新版」。
  - AC3：拔掉網路後打開設定（距離上次查詢超過 1 小時）→ 顯示「無法檢查更新」；點擊 → 提示「yt-dlp 更新失敗」，已經在播放的格子不受影響。
  - AC4：自動更新進行中打開設定 → 顯示「正在更新…」；點擊無作用。
  - AC5：1 小時內第二次打開設定 → 不重新查詢，直接顯示上次的結果。

### R94：版本號
- 描述：程式版本號從 0.6.1 更新為 0.7.0，並打包（安裝檔內附 yt-dlp）。
- 驗收條件：
  - AC1：`npm run dist` → 產生 `release/MultiView-Setup-0.7.0.exe`；安裝後程式的版本是 0.7.0，安裝資料夾裡有內附的 yt-dlp。

## 8. 非功能需求

- **效能：** 開啟程式不因 yt-dlp 的準備、更新而變慢（R91、R92 都在背景）。2×2 播 4 路 yt-dlp 1080p 直播 30 分鐘不當掉、不凍結。
- **跨網站存取許可：** 只補給程式畫面自己發出的串流請求（請求來源是程式畫面的網址），不改動內嵌播放器（來源是 YouTube）和網頁來源的請求，避免影響現有的 YouTube 播放。
- **解除安裝：** 解除安裝時保留 `%APPDATA%\MultiView`（現有的安裝設定），使用者的 yt-dlp 也一起保留。
- **安全：** 主程序再驗一次影片代碼（11 碼的英數、`_`、`-`），自己組 YouTube 網址；執行 yt-dlp 不經過命令列殼層（參數用陣列）。解析得到的串流網址不寫進設定檔（會過期）。
- **檔案大小：** 安裝檔多約 23MB（yt-dlp；0.7.0 實際 143MB，0.6.1 是 120MB）。
- **JS 執行環境：** yt-dlp 解析 YouTube 需要的 JS 執行環境用程式本身（以 Node 模式執行 MultiView 的執行檔），不另外附 Deno，也不依賴電腦上裝的 Node。
- **測試：** 解析結果的判讀、錯誤分類、快取與佇列、自動更新的協調、版本比較、設定檔相容寫成單元測試；播放與退回以手動驗收。

## 10. 計畫與目前程式的對照（2026-11-06）

計畫和可行性測試是依幾乎是初版的程式寫的。對照 0.6.1 的結果：

| 計畫的內容 | 目前程式 | 處理 |
|---|---|---|
| m3u8 的畫質用 `capLevelToPlayerSize` | 已經有畫質選單與依格子大小限制畫質（R24、R32），而且刻意不用 `capLevelToPlayerSize`（hls.js 1.7.3 播放中打開不生效） | 沿用現有做法，不照計畫 |
| `VideoPlayer` 的重試、從原時間點繼續（`resumeAt`） | 已經有；另外已有觀看進度 `startAt`（R55） | 沿用，只加上「解析」這一步 |
| 主程序補 CORS（計畫 4.3，連 `*.youtube.com` 一起補 `*`） | 沒有任何 CORS 補丁；主視窗和內嵌播放器共用同一個 session | 只補 `googlevideo.com`、而且只補給程式畫面發出的請求（第 8 節），不能照計畫對 `youtube.com` 一律補 `*`，否則可能影響內嵌播放器 |
| 移除 `before-input-event` 轉送、「直接操作」、`onShortcut`、`will-prevent-unload` | 內嵌播放器保留，這些都還需要 | 不移除（第 5 節） |
| 錯誤原因 `ErrorReason`、Cell 依原因顯示訊息 | 失敗都退回內嵌（R90） | 不需要；格子不必知道原因 |
| 工具列「更新 yt-dlp」按鈕 | 已有「⚙ 設定」選單（R49）與版本號（R76） | 放進設定選單（R93） |
| 設定檔只存網址 | 設定檔已有許多欄位，`version` 仍是 1 | 新增兩個欄位，`version` 不變 |
| 打包是可攜版 | 已改成 NSIS 安裝檔（R44），已有 `extraResources`（easylist） | 在現有的 `extraResources` 加一條 |
| 「YouTube 禁止內嵌的影片也能播」 | 已有 R48、R49 網頁播放 | 兩者並存：yt-dlp 失敗才退回內嵌，再依 R49 |
| 小視窗、▾ 選單、預覽縮圖（計畫沒有） | 都只用影片代碼，不依賴內嵌播放器 | yt-dlp 播放照常可用（R89） |

可行性測試結果（使用者在另一台電腦以舊版程式測試）仍然有效的部分：yt-dlp 能取得直播的 HLS 與一般影片的 360p、畫面的來源網址相同（都是本機 http），所以 CORS 的結論不變。
