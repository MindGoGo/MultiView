- 功能代號：`installer-and-youtube-fixes`
- Jira：無
- 狀態：已確認、已複查、已實作
- 最後更新：2026-10-09
- 前置規格：[multiview-player](multiview-player.md)（R1–R11）、[web-page-source](web-page-source.md)（R12–R18）、[player-controls-and-lists](player-controls-and-lists.md)（R19–R25）、[cell-play-and-page-menu](cell-play-and-page-menu.md)（R26–R29）、[captions-and-quality-menu](captions-and-quality-menu.md)（R30–R33）、[brightness-and-volume-popup](brightness-and-volume-popup.md)（R40–R43）。本規格的需求編號從 R44 開始；R34–R39 仍保留給本機播放與下載功能。

## 1. 背景與目標

使用 0.3.1 時發現三個問題：

1. 打包成單一 exe 的程式每次開啟都要先把約 100MB 的內容解壓縮到暫存資料夾，實測約 4.5 秒才出現畫面；程式本身只需要約 0.5 秒。
2. 「直接操作」YouTube 時，點暫停畫面的「更多影片」或影片結束後的推薦影片沒有反應。原因：這些是「在新視窗開啟 youtube.com」的連結，程式為了安全一律擋掉新視窗。標題、頻道、YouTube 標誌也一樣沒反應。
3. YouTube 選了固定畫質（例如 1080p）時，暫停畫面的正中央出現一條細細的深色橫線。原因：選固定畫質時，播放器以該畫質的大小排版再縮放（R32），YouTube 的暫停畫面在縮放後於正中央出現接縫；選「自動」時不縮放，沒有這條線。

目標：改成安裝版讓開啟變快；YouTube 裡的影片連結在同一格播放、其他連結用瀏覽器開啟；消除暫停畫面的橫線。

## 2. 範圍

**包含：**
- 改成安裝版（R44）
- YouTube 播放器裡的連結（R45）
- 暫停畫面的橫線（R46）
- 版本號更新並打包（R47）

**不包含：**
- 單一 exe（portable）版本：不再產生（使用者選擇只要安裝版）
- 自動更新：新版本仍需手動下載安裝檔執行
- 程式碼簽章：沒有憑證，安裝檔不簽章
- 網頁來源（`<webview>`）裡的新視窗連結：維持擋掉
- mp4、m3u8 來源：沒有連結，不受影響

## 3. 共用定義

- **YouTube 影片連結：** 網址能被辨識為 YouTube 影片的連結，包括 `youtube.com/watch?v=…`、`youtu.be/…`、`youtube.com/live/…`、`youtube.com/embed/…`（與第一版 R2 可貼上的 YouTube 網址相同）。Shorts 不能放進格子（第二版 R12），視為不是影片的連結。帶有播放清單、開始時間或其他參數時只播放那一部影片，從頭開始；放入格子的網址整理成 `https://www.youtube.com/watch?v=<影片代碼>`（歷史紀錄也記這個網址，同一部影片不會因為參數不同而記成多筆）。
- **連結所在的格子：** 使用者點擊連結的那一格 YouTube 播放器。YouTube 播放器裡的連結只有在「直接操作」時才點得到（第一版 R3），所以就是目前「直接操作」中的那一格。沒有格子在「直接操作」時（例如點擊的同時直接操作剛好結束），影片連結也改用系統瀏覽器開啟。

## 4. 需求清單

### R44：安裝版
- 描述：
  - `npm run dist` 改成產生 Windows 安裝檔 `release/MultiView-Setup-<版本>.exe`，不再產生單一 exe。
  - 安裝檔不需要系統管理員權限，只安裝給目前的使用者。執行後直接安裝（不詢問安裝位置），完成後自動開啟程式，並建立桌面捷徑和「開始」功能表捷徑。
  - 已安裝舊版時，執行新版的安裝檔會直接覆蓋更新。程式正在執行時，安裝檔會提示先關閉程式。
  - 可以從 Windows「設定 → 應用程式」解除安裝。解除安裝不刪除設定與清單，重新安裝後仍然保留。
  - 設定、清單存放的位置和單一 exe 版本相同，所以從單一 exe 版本改用安裝版時，版型、格子、清單都會保留。
- 驗收條件：
  - AC1：`npm run dist` → 產生 `release/MultiView-Setup-0.3.2.exe`，沒有產生 `*-portable.exe`。
  - AC2：在沒有安裝過的情況下執行安裝檔 → 不跳出系統管理員權限的詢問；安裝完成後程式自動開啟；桌面和「開始」功能表有 MultiView 捷徑。
  - AC3：關閉程式後從桌面捷徑開啟（不是安裝後的第一次開啟）→ 2 秒內出現畫面並載入格子（同一台電腦上單一 exe 版本約 4.5 秒）。
  - AC4：先用 0.3.1 單一 exe 設定好格子和清單，再改用安裝版開啟 → 版型、格子、清單都和原本一樣。
  - AC5：從 Windows「設定 → 應用程式」解除安裝 → 捷徑和程式移除；重新安裝後設定仍然保留。

### R45：YouTube 播放器裡的連結
- 描述：
  - 在 YouTube 播放器裡點擊會開啟新視窗的連結時：
    - 是 YouTube 影片連結、而且不是這一格目前的影片 → 連結所在的格子換成那部影片，和在這一格「更換網址」貼上新網址的結果相同（第一版 R2、第三版 R23 的歷史紀錄；音量、靜音、亮度、畫質、字幕設定保留）。
    - 是這一格目前的影片（例如點標題）、或不是影片的 `http`／`https` 連結（例如頻道名稱、YouTube 標誌）→ 用系統預設的瀏覽器開啟。
    - 其他網址（不是 `http`／`https`）→ 不處理，維持擋掉。
  - 換成新影片後自動開始播放（和貼上新網址相同）。
  - 程式本身不會開出新的視窗。
- 驗收條件：
  - AC1：「直接操作」YouTube 格子，暫停後點「更多影片」裡的一部影片 → 這一格換成那部影片並開始播放；其他格不變；歷史清單多一筆，網址是 `https://www.youtube.com/watch?v=<影片代碼>`。
  - AC2：影片播完後點推薦影片 → 同 AC1。
  - AC3：換成新影片前這一格的音量 30、亮度 80% → 換成新影片後仍然是音量 30、亮度 80%。
  - AC4：點播放器左上角的影片標題 → 系統預設的瀏覽器開啟這部影片的 YouTube 頁面；這一格不變。
  - AC5：點頻道頭像或 YouTube 標誌 → 系統預設的瀏覽器開啟對應的頁面；這一格不變。
  - AC6：網頁來源的格子裡點擊會開新視窗的連結 → 和以前一樣沒有反應。

### R46：暫停畫面的橫線
- 描述：
  - YouTube 選了固定畫質、播放器需要縮小時（畫質比格子大），改用不會產生接縫的縮放方式，暫停畫面不再出現橫線。
  - 播放器需要放大時（畫質比格子小）維持原本的縮放方式：新的方式放大時會提高畫面密度，YouTube 可能因此選擇比所選更高的畫質（第 8 節技術說明）。
  - R32 的畫質行為不變：播放器仍以所選畫質的大小排版，YouTube 回報的畫質和改之前相同。
- 驗收條件：
  - AC1：`1` 版型、視窗約 1700×950，有 1080p 的 YouTube 影片（例如 `aqz-KE-bpKQ`）選 1080p 後暫停 → 畫面正中央沒有深色橫線。
  - AC2：`2×2` 選 720p 後暫停 → 正中央沒有深色橫線。
  - AC3：AC2 的情況下，YouTube 回報的畫質仍然是 hd720（R32 AC2）。
  - AC4：選「自動」時的畫面和改之前相同。

### R47：版本號
- 描述：程式版本號從 0.3.1 更新為 0.3.2，並打包。
- 驗收條件：
  - AC1：`npm run dist` → 產生 `release/MultiView-Setup-0.3.2.exe`；安裝後程式的版本是 0.3.2。

## 8. 非功能需求

- **效能：** 安裝版從捷徑開啟到載入格子 2 秒內（R44 AC3）。
- **安全：** 只有 `http`／`https` 網址會交給系統瀏覽器；程式內不開新視窗；網頁來源的規則不變。
- **技術說明（已先驗證）：**
  - 開啟時間：單一 exe 約 4.5 秒，直接執行解開後的程式約 0.5 秒。
  - 橫線：`2×2` 選 720p 時，播放器以 `transform: scale(0.4986)` 縮放，暫停畫面第 179 列（格子高 359 的正中央）的亮度比上下低約 15%；改用 CSS `zoom` 縮放後消失，YouTube 播放器內部仍是 1281×720、回報 hd720。
- **實作結果：**
  - 安裝版安裝在 `%LOCALAPPDATA%\Programs\multiview`，解除安裝資訊登記在目前使用者底下；從安裝後的程式開啟約 0.56–0.79 秒。
  - 橫線只在 YouTube 暫停畫面的標題、按鈕顯示時出現（叫出它們需要滑鼠移到播放器上），所以先前幾次截圖沒有看到。2×2、720p：`transform` 時正中央那一列亮度 217（上下 255），`zoom` 時 255；YouTube 仍回報 hd720。
  - 放大：`1` 版型選 480p 時，`zoom` 讓播放器內部的畫面密度變成 1.5，YouTube 回報 hd720；`transform` 這次也回報 hd720（這部影片 YouTube 本來就不急著降低畫質），無法比較出差異。依技術風險的處理方式，放大時維持 `transform`。
- **技術風險：**
  - 安裝檔沒有簽章，第一次執行時 Windows SmartScreen 可能顯示「Windows 已保護您的電腦」，要按「其他資訊 → 仍要執行」。
  - 用 `zoom` 放大（大格子選低畫質）時，YouTube 可能因為畫面密度變高而選擇比所選更高的畫質；實作時驗證，若發生則放大時維持原本的縮放方式，並回報。
- **測試：** 連結的分類規則（影片／同一部影片／其他網址／沒有直接操作的格子）與網址整理寫成單元測試；安裝、開啟時間、點擊連結、橫線以手動驗收（點擊 YouTube 裡的連結需要真實滑鼠）。
